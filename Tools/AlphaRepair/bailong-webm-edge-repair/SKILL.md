# 白龙透明动画修边

先确认目标动作 ID、实际播放文件和缺陷帧。只处理用户指定的范围。保留原件、透明通道、原尺寸及时间轴。从零开始时以原始帧为输入，继续某一版时用指定副本。沿用角色原画与配色，不生成、补画或整体调色。

## 逐帧处理

1. 已有 RGBA PNG 时直接读取。透明 VP9 WebM 用带 `libvpx-vp9` 解码器的 FFmpeg 离线抽帧。对照原尺寸帧、缩放结果与桌面效果，定位缺陷首次出现的环节。
2. 在新的批次目录中按 `originals/<动作ID>/<帧号>.png` 放置输入。两份脚本依赖 NumPy、Pillow，路径相对于本 skill 目录。Windows 可以用 `py -X utf8` 或虚拟环境的 `python.exe -X utf8` 运行。
3. 使用 `python -X utf8 scripts/repair_frames.py --batch <批次> --mode conservative`，或按缺陷选择 `aggressive`。前者优先保留相连的紫色描边，后者也清封闭空隙和弱过渡。脚本默认选择后者，这些阈值来自早期 720 × 720 素材。在有独立粒子、光效或淡出符号的动作里，按该动作决定保护区域。目标是可见的污染，并非删除所有封闭区域或孤立像素。[清理脚本](scripts/repair_frames.py)
4. 在 `repaired/` 和 `masks/` 对照同帧。任意帧号可放入单独的试验批次，正常运行即可。只有需要固定抽取第 1、48、96 帧时才用 `--samples`。清理阶段输出的 PNG 保留输入 RGB，重新编码后另行评价色彩和 Alpha。
5. 需要局部平滑时，将清理结果复制到另一个批次的 `originals/`，运行 `python -X utf8 scripts/smooth_frames.py --batch <新批次>`。新增边缘像素使用邻近颜色的预乘加权结果。若清理误删角色细节，应先缩小删除范围或从原始同帧恢复对应区域。[平滑脚本](scripts/smooth_frames.py)

交付时标明动作、输入来源、处理模式和输出位置。技术核对关注帧数、尺寸及蒙版范围，动态效果依据实际播放结果。按本次约定安排视觉检查。若用户自行审片，提供修后帧及对应蒙版。原素材与修复副本分开保存，替换应用资源及对外分发按当次要求执行。需要追溯四个仓库的修复方法或区分 Swift 与 Qt 的不同母版时，参阅[素材修复对照](references/四个仓库的素材修复对照.md)。
