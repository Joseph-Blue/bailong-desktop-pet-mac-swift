### 气泡与显示

- 消息、短进展、额度和预览共用 `Bubble` 的非激活浮动面板。
- **滚动视口与行宽（`BubbleBodyScrollView`／`BubbleBodyLayout`）**：统一计算正文排版宽度，左右边距对称（默认 `21pt` 随气泡比例缩放，小比例下至少容纳系统滚动条轨道加 `2pt` 间距）。纵向滚动条占用右侧边距，`lineFragmentPadding = 0`，滚动条显隐与窗口尺寸过渡均不改变文本换行宽度；仅内容纵向溢出时启用原生滚动条。多行阅读与输入容器关闭横向弹性并固定 `x = 0`，可滚动纵向区域启用 AppKit 原生边缘回弹（不滚动的短进展气泡除外）。
- **增量排版与首行稳定（`MessageTextView`）**：共用单一 TextKit 容器完成高度测量与显示，更新时保留未变化前缀、仅替换变化尾部。无用户选区时写入正文后将插入点保持在 `{0, 0}`，并拦截容器 `setFrameSize` 期间的自动 `scrollToVisible`，防止任务信息栏异步挂载或窗口伸缩把视口拉向文末。`BubbleBodyScrollView` 固定 `documentView` 原点为 `.zero`，按 `BubbleMotion` 落地的目标视口高度判定纵向溢出。普通气泡打开、切卡与正文变更时在原生 clip／document 布局完成后执行单次回顶；用户开始滚轮或拖动滚动条即取消待执行回顶，后续排版保持当前阅读位置（新开或切卡后忽略此前残留的触控板惯性滚轮，直至产生新的滚动手势；外观配色刷新保留阅读位置列于 TODO）。
- **2 秒短进展气泡**：首行与主气泡进展栏、任务概览共用标题、操作图标和结果角标。盲文按轮次是否执行中显示，等待审批或回答时由对应状态图标表示。第二行只显示首行之外的公开细节，例如已显示搜索目录时补充关键词，已显示文件名时补充目录。没有补充时按一行排版。标题和正文各自单行尾部省略，截断时悬停可读对应文本。专用 clip 保持顶部，窗口按内容自然高度显示。可见期间内容变宽或变窄时，宽度与高度共用 140ms 过渡。位于桌宠上下方时以角色中心为横向锚点，位于左右两侧时固定靠近角色的一边；靠屏幕边缘时逐帧限制在可用区域内。关闭“动态效果”或开启系统“减少动态效果”时直接采用新尺寸。同轮次相同标题、补充和图标状态只展示一次，内容变化后重新计时。任务结束或停止观察时释放快照。重连沿用连接状态提示。
- 任务卡和临时气泡共用 `BubbleContent`。卡片渲染直接读取 `BubbleCard` 的问卷、审批和底栏，并按卡片身份保留已挂载表单与草稿。
- 问卷和审批气泡的底行等分为两列，左列翻阅消息卡，右列为「转到 Codex」。新版项目问卷只显示「这个问题需要你转到 Codex 回复。」和跳转操作。可在桌宠内回答的问卷在输入框下方排列「< 上一题」「跳过」「下一题 >」或末题操作。普通选项与「其他」共用首行对齐和文字缩进。
- **卡片栈与停留计时（`BubbleCardStore`／`BubbleCountdown`）**：卡片保留上限为 `5～100`（默认 `50`），近期结束任务数为 `1～20`（默认 `5`），展示优先级依次为“待处理审批或问卷 ＞ 任务消息 ＞ 任务概览或互动台词”。用户手动翻阅或填写问卷期间不自动切卡，同条流式消息原地更新，已处理请求自动移除；额度结果、设置预览与普通动作对白不写入卡片栈。单卡固定显示 `1 / 1` 并置灰翻页箭头；鼠标移入暂停倒计时、移出续计，翻页重新计时，审批、问卷与错误卡片保持常驻直至用户手动处理。
- **任务概览与互动触发**：仅鼠标动作设为 `random`（“显示任务进度、播放随机动画”）时展示并复用单张 `taskOverview` 卡片，每次触发刷新工作中台词与会话最新轮次列表并移至栈尾；`randomAnimation`、菜单随机动画与设置动作试播只播放动画和单句台词。助手消息卡按真实消息 ID 区分，不跨轮次合并。
- **四向定位与刘海过渡（`BubblePlacement`）**：气泡与输入窗随桌宠拖动实时跟随，动作切换与吸边不主动收起气泡。普通状态优先桌宠下方或上方，刘海收纳状态下的大气泡按“左、右、下、上”顺序避让屏幕边界与输入窗；位于下方时固定上边缘向下伸展，位于上方时固定下边缘向上伸展。在 `0.3s` 刘海收纳／展开过渡期内，气泡锚点按收纳与展开两端的可见轮廓线性插值（复用 `dockProgress`），不跟随 `180°` 旋转过程中的外接矩形起伏。
- **状态图标、计时器与文字动效**：
  - 气泡、临时输入与工作区状态条复用 `BubbleCloseButton`，无边框图标使用零对齐边距；圆形悬停底色按按钮短边居中绘制，Auto Layout 或直接设置 frame 时均不拉成椭圆。
  - `InlineStatusLayout` 对齐文字基线与图标大写字高中心，加载盲文按完整 `⣿` 字形单元固定槽位；等待用户审批或回答时隐藏执行盲文并继续保留任务计时。
  - 任务气泡和任务概览中，运行中的计时数字与秒表图标使用正文色 `labelColor`。轮次结束后按结果着色。
  - `TaskActivitySymbolView` 在默认比例下为主进展／概览采用 `15pt`、短进展／待处理标题采用至少 `16pt` 的 `.semibold` 等宽高槽位图标；失败、拒绝、取消／中断分别在操作图标旁附加语义色状态角标。
  - 右上角秒表按任务真实开始时间每秒刷新（`MM:SS`／`H:MM:SS`），外部任务结束优先取 `completed_at`；完成定格为绿色，失败／取消／中断定格为红色。
  - `ProgressTextEffects` 标题扫光周期为 `1.2s` 扫过＋`2.8s` 停顿，保留不透明黑／白底字，浅色黑字扫亮灰、深色白字扫暗灰；峰值向白／黑混合 30%，系统开启“增加对比度”时降至 18%，不扫至纯白／纯黑。扫光按 16 档离散高亮缓存属性字典原型，`2.8s` 停顿期直接复用整段底色属性，避免逐帧新建浮点 `NSColor` 污染 UIFoundation 全局弱属性字典表。`ProgressMarqueeView` 仅在标题超宽时以 `28pt/s` 循环滚动，首尾以带留白的 `·` 衔接，同文刷新保留相位。隐藏、销毁、任务结束或开启“减少动态效果”／关闭“动态效果”时停止计时器。
- **窗口动效、退出与玻璃材质**：
  - `BubbleMotion` 默认开启：出现 `160ms` 淡入＋`4pt` 位移、关闭 `120ms`、高度伸缩 `140ms`、材质切换 `160ms`。尺寸变化先完成玻璃容器布局，再按窗口实际落地尺寸排版正文视口。菜单与信号退出先在常规 RunLoop 完成淡出、停止任务与保存数据后再调用 `NSApp.terminate`；系统关机等直接进入 `terminateLater` 的路径同步向 `.modalPanel` 注册过渡计时器。
  - macOS 26+ 默认使用单窗口 `NSGlassEffectView.contentView` 承载正文与衬底（支持跟随系统 `regular` 或手动 `clear`＋`0～1` 不透明度；开启“减少透明度”或 macOS 14～15 自动使用普通实色背景，切换材质保留原响应者且不激活应用）。
  - 主气泡、短进展、预览、临时输入与工作区状态条在启用玻璃材质时共用 1 物理像素的 `GlassEdgeHighlight` 内侧渐变亮边（顶部较亮、侧边渐弱，由渐变图层和圆角描边遮罩合成，不响应鼠标）。气泡显示底部 Git／文件信息栏时底边距收紧为 `8pt`（正文与按钮区上下各留 `4pt`），无信息栏时保持 `16pt`。

### 输入与窗口

- **带尖角的气球**。气球以尖角指向触发它的界面元素，包括 Git 详情、本轮文件修改详情、模型选择、设置数值编辑和会话搜索。原生 `AnchoredPopover` 和会话搜索面板共用窗口层级规则，最低采用 `.statusBar`，置于普通窗口和浮动窗口上方。

- **任务信息栏与工作区状态条**
  - 气泡内的「任务信息栏」（`taskInfoBarEnabled`，默认开启）位于正文下方、底部操作按钮上方，复用 `WorkspaceStatusView` 单行展示 Git 仓库状态与本轮文件增删（隐藏目录名；干净 Git 仓库照常显示，非 Git 目录且无本轮文件改动时隐藏）。紧凑气泡以胶囊外沿对齐正文，Git 和本轮文件统计按钮的内边距、圆角及悬停范围均包含在布局内。同会话主气泡已展示状态行时，2 秒短进展气泡自动去重；任务概览受同一开关控制，行底左侧显示工作区当前 Git 状态，右侧显示该轮文件增删。长分支名居中省略，空间更紧时文件统计缩为文件数或图标，点击可查看完整详情。
  - 独立的「工作区状态条」（`WorkspaceStatusPanel`，由 `gitWindowEnabled` 控制，默认关闭）采用不可成为 key 的 `PetWindow`（`allowsInput = false`，全空间跟随且不参与窗口循环），只设**常驻显示**与**隐藏**两种状态。桌宠右键和状态栏的「快捷开关」根据当前状态动态显示「显示工作区状态条」／「隐藏工作区状态条」，点击状态条左侧关闭按钮同样将 `gitWindowEnabled` 置为 `false`。面板单行排列关闭按钮、目录／仓库名、Git 状态与本轮文件统计（最大宽度 `640pt`，优先排在桌宠下方，空间不足转上方）；桌宠隐藏时暂隐并在桌宠恢复时按开关状态还原，关闭开关即停止后台 Git 查询与文件监听。
  - 「快捷开关」底部通过分隔线单列「显示桌宠」／「隐藏桌宠」，和状态栏菜单首项共用显隐动作及动态名称、图标。
  - 「快捷开关」在「任务气泡提醒」下方提供「思考与工具进展小气泡」，用原生勾号显示 `progressToastEnabled`。与设置页共用偏好和前置条件，任务气泡或任务过程消息关闭时，快捷菜单中置灰，设置页中收起，并保留原值。工作区状态条入口位于「全屏时自动隐藏」上方，后者使用 `square.arrowtriangle.4.outward` 图标。
- **Git 状态查询与文件监听（`GitWorkspaceRequest`）**：面板可见时通过 `/usr/bin/git --no-optional-locks -C <cwd>` 只读解析 `porcelain=v2 -z` 状态及分支／上游信息（单命令超时 `8s`、输出上限 `8 MiB`，不启动登录 shell、不执行 `fetch`、不改动索引）。可见的气泡、概览行与状态条按工作目录共用一份查询与监听（`GitWorkspaceMonitor`），最后一个入口退出时释放。对 Git 工作树与实际 `.git`／`commondir` 建立 `FSEvents` 递归监听，经 `400ms` 防抖合并查询，查询期间的新事件合并补查一次；非 Git 目录及隐藏／关闭状态下不驻留监听器。
- **Git 状态标识与详情弹窗（`WorkspaceFileTable`）**：上游所用远端或唯一远端为 `github.com` 时显示 Primer Octicons GitHub 图标，其他已识别远端显示 `network`，本地或未选定远端使用 Lucide `git-branch` 图标（HTTP(S) 剔除用户信息，主流代码托管 SSH 地址映射为网页链接）。紧凑状态使用等宽半粗字体。默认 bash-git-prompt 符号风格显示绿色 `●N` 已暂存、橙色 `✚N` 未暂存、正文色 `…N` 未跟踪、红色 `✖N` 冲突、紫色 `⚑N` 贮藏 (Stash)、绿色 `✔` 工作区干净、蓝色 `↓N / ↑N` 上游提交差。Git 详情和辅助功能显示 `贮藏 (Stash) N 条`，数量为零时省略。未跟踪计数与详情分组标题共用系统正文色 `labelColor`。本轮文件改动统计读取所属轮次已完成的 `Turn.fileEdits`（`+N −N`）。Git 详情与文件详情共用原生透明列表 Popover（应用内外非锚点点击经 `PopoverDismissal` 自动收起，显式聚焦标准窗口前同步关闭；单击选中、双击在访达中定位、右键可在访达中显示或拷贝当前文件路径，也可按列表顺序逐行拷贝去重后的绝对路径。Git 详情的文件行和分组标题可拷贝本组或整张列表，本轮文件修改可拷贝整张列表）。触控板重压文件行或有菜单的分组标题时，第二段下压直接打开同一个右键菜单。
  - 上游详情区分未设置、上游引用缺失与 Git 返回的落后／领先计数。状态条、详情、悬停图例和辅助功能均按先落后、后领先的顺序显示。详情中的上游差异使用蓝色，贮藏使用紫色，符号随显示风格更新。分离 HEAD 时，当前提交有标签则显示 `#标签`（多个标签按名称排序取第一个），否则显示 `@短提交号`。`git am` 显示「应用补丁中」，能读到当前步数和总步数时显示「变基中 2/5」一类进度。
- **非激活输入与会话草稿（`ChatComposer`／`ChatNavigation`）**：
  - 临时输入面板采用 `.nonactivatingPanel`，`ContentCursorPanel` 将 `⌘X`／`⌘C`／`⌘V`／`⌘A` 直接路由至面板内当前第一响应文本视图，不依赖前台应用菜单栏。
  - 临时输入窗在排版确定目标尺寸后通知桌宠重新定位。窗口动画逐帧调整显示尺寸时由 `BubbleMotion` 绘制。
  - 手动打开临时聊天或快捷回复时，收起主气泡和短进展，并使先前的额度回执失效。主动查询额度、显示任务概览或互动气泡时，目标气泡显示后收起聊天。后台进展、完成和错误通知保留聊天及草稿。显式打开设置也会收起聊天，文件夹选择器和审批／问卷 sheet 保留宿主。
  - 「技术详情」在原生对话框内显示任务、动画或额度错误报告。「错误与恢复」以独立窗口显示启动与数据恢复问题。两者共用圆角、可滚动和可复制的正文区域。
  - 临时输入、历史回复与气泡问卷共用 `MessageInputBox`。多行 `MessageEditor` 负责文本选择、插入点和输入法组字。`TextContextMenu` 为应用自定义的文本右键菜单提供剪切、拷贝、粘贴和全选。有文字选区时，自定义文本右键菜单和顶部「编辑」菜单均在全选之后显示「使用〈搜索引擎〉网页搜索」和可用的系统「翻译」。搜索按「通用 → 网页搜索 → 搜索引擎」生成查询网址，交给系统默认浏览器打开，默认使用 Bing。翻译沿用 AppKit 的原生动作，菜单标题显示为「翻译」。文本右键菜单将可用的撤销与重做放在剪切、拷贝、粘贴之后，与全选同组。存在可朗读文本或正在朗读时，文本右键菜单和顶部「编辑」菜单显示系统「语音」子菜单。焦点位于可编辑文本中时显示 AppKit 的「开始听写…」和「表情与符号」，沿用系统图标和快捷键。发送与换行沿用 `SendShortcut`（`⌘↩`、`↩`、`⌃↩ 或 ⌘↩`），快捷键提示位于发送或确认按钮。审批区使用只读正文和原生操作按钮。
  - 临时输入、历史回复、气泡问卷与会话选择器的搜索框共用 `TextInputFocusRing`。它跟踪所属键窗口及第一响应者，窗口恢复编辑焦点或点入输入框时，以系统焦点色 `keyboardFocusIndicatorColor` 直接描出圆角轮廓，并在 `0.30s` 内淡入、收拢。窗口失焦或输入区转为只读时收起外圈。关闭动态效果或开启系统「减少动态效果」时直接显示静态轮廓。

  - `ChatNavigation` 与 `ChatDraftCache` 按入口（临时输入／历史窗口）和会话分别保存内存草稿，异步发送回执核对原目标身份，不会清空用户随后切换到的会话草稿。
  - 临时输入窗按对话类型和本地会话标识恢复上次选择。首次使用默认人设对话。已选项目记录缺失时保留项目模式，等待重新选择。历史窗口独立浏览；快捷回复按来源卡片选中会话。
  - 临时输入窗顶部采用原生分段控件切换人设／项目对话，会话选择器同行右对齐。搜索与会话列表由锚定按钮的非激活子面板承载，沿用 AppKit 弹窗材质。选择会话后焦点回到临时输入。Esc 先清空搜索词，搜索词为空时关闭面板并回到正文。按当前模型框和操作按钮宽度排版，能放下的短状态与模型框同行，其余状态另起一行并在 `96pt` 高度上限内纵向滚动。
- **窗口与 Dock 生命周期（`InterfaceWindows`）**：仅登记未关闭的标准窗口（设置默认 `1040×900pt`、正文上限 `780pt`；历史初始 `1100×850pt`；点击绿灯填满当前屏幕可用区域，不进入独立全屏空间）。存在打开或最小化的标准窗口时保留 Dock 图标，全部关闭后自动收回 Dock 图标；显式打开、Dock 图标召回与最小化缩略图恢复统一经 `InterfaceWindows.focus` 先收起非激活面板浮层、解除最小化并无条件执行 `NSApp.activate(ignoringOtherApps: true)` 与下一轮主队列前台／key 复核（防止非激活面板置位 `NSApp.isActive` 导致跳过真实应用激活），后台刷新不召回窗口。`⌘Q` 或 Dock 退出仅关闭当前标准窗口，彻底退出桌宠通过右键／状态栏／应用菜单触发。再次启动应用会主动召回隐藏或吸边的桌宠。文件选择面板（`PanelPresentation`）与取色板（`CenteredColorWell`）首次打开时在当前屏幕居中一次，后续允许自由拖动；`HoverHelp` 悬停延迟 `200ms`、淡出 `80ms`。

### 会话与任务

- **双通道隔离**：
  - **内置人设会话**：由 `ChatController` 管理独立 `codex app-server --listen stdio://` 子进程，连接内复用已加载线程身份，按轮携带所选模型、推理档位与桌宠人设指令，由 `TaskMessageAccumulator` 聚合公开事件。
  - **外部项目会话**：`DesktopHistoryReader` 与 `DesktopSync` 只读投影桌面端 SQLite 与实时状态。通用设置末尾的「Codex 项目对话 → Codex 桌面端通信方式」以双段控件显示新版与旧版。桌宠读取桌面应用版本，`26.1117` 系列起自动选新版，此前选旧版。两档适配基准分别为 `26.1117.41037` 和 `26.1111.21308`。未检测到有效版本时默认选新版。版本行始终显示按版本得出的建议。手动选择保存到 `projectSendChannel` 并优先生效，恢复通用页默认值后重新跟随版本。新版通过桌面端随附 CLI 的 `queue` 向指定会话提交文本。用户主动发送时先打开所选原会话，桌面端已退出时同时启动应用。旧版由 `DesktopConversationSession` 读取模型设置、提交回复（`thread-follower-start-turn` v2）或插话（`steer-turn` v1），沿用原会话配置。切换选项后已发出的请求继续按原请求处理。两档共用历史观察。新版由项目 Hook 处理命令审批，旧版实时订阅及审批决定沿用原 IPC。
- `DesktopConversationSession` 保存观察器投影的 `ObservedDesktopTurn`。新轮回复与插话按所属会话最新轮次的 ID 和协议状态判定，任务概览另行附加显示字段。缺少实时轮次时，历史终态可用于发起新轮。观察、发送前复核和概览共用终态集合，`interrupted`、`cancelled`、`canceled` 均归入已停止，只有 `completed` 表示成功。
- 人设会话的模型弹窗可通过模型菜单与推理强度滑块选择档位，底栏提供「刷新模型」和「与 Codex 同步」。
- **模型供应商**：人设会话通过 `config/read` 读取工作区配置的供应商 ID、模型和推理档位。`APIProviderDirectory` 优先匹配 `base_url` 主机（完整域名或点号分隔的子域名），未命中时按 provider ID、别名或完整名称回退；Kimi 区分中国站与国际站，智谱区分 BigModel 中国站与 Z.AI 国际站。完整名称用于额度气泡、帮助和错误，模型摘要使用 `Kimi CN`、`Kimi Global`、`智谱 GLM`、`Z.AI` 等短名；未知供应商继续使用配置名称。新会话跟随该供应商，继续旧会话时核对 `thread/start`、`thread/resume` 返回的供应商。第三方默认模型未出现在目录时，摘要使用配置的模型和档位，可选档位由 Codex 模型目录提供。外部会话的供应商 ID 取自原会话的只读记录，模型和推理档位沿用桌面端会话设置。
- **模型摘要的账号与图标**：人设会话在供应商为 `openai` 时通过当前 app-server 的 `account/read(refreshToken:false)` 读取账号类型。项目会话优先采用原会话 IPC 返回的供应商，并从本机线程索引投影会话创建时是否有 ChatGPT 账号记录的布尔值。ChatGPT 会话省略 OpenAI 名称，API 供应商和缺少账号标记的会话显示供应商名称。可用的第三方图标置于摘要开头并与文字居中。
- **模型框宽度**：人设选择框和项目只读模型框共用 `ModelSummaryButton`；自然宽度上限为 `320pt`。同一行存在状态文本时，`ModelSummaryLayout` 先保留完整状态宽度，状态最多占可用宽度的 55%，模型至少保留 45%；空间不足时状态整体移到下一行，摘要先截断并以悬停显示全文。人设选择变更后，在同一次更新里按新摘要排版，原生弹窗以按钮边界定位。项目会话收到设置回执后沿用同一尺寸计算。选用旧版通道且本机通信未就绪或原会话未加载时，模型框显示「发送首条消息后显示模型信息」。被动读取有其他错误时提供「重新读取」。历史输入区按当前可见的模型框和操作按钮测量右栏最小宽度。
  - 项目只读模型框的第三方彩色图标使用与文字相同的排版槽位，独立于置灰的按钮文字绘制。模板图标沿用原生置灰样式。
- **模型速度档位**：模型目录读取 `serviceTiers`，仅 `openai` 提供方且目录含快速档时启用「bolt · 1.5倍速度」原生开关，位于推理强度同行右侧。偏好 `petChatFastMode` 默认关闭，按入口／会话保留选择；切到不支持的模型禁用控件并保留选择，设置导入导出及全部恢复默认值覆盖该键。「与 Codex 同步」同时读取 `service_tier`，未指定时沿用目录的 `defaultServiceTier`。内置每轮通过 `serviceTier` 发送目录中的快速档 ID，关闭时显式发送 `default`，覆盖旧线程档位；不改写 Codex 全局配置。
  - 模型摘要使用 SF Symbols `bolt` 前置附件，按视图外观取系统标签色。快速模式说明挂在开关上，外部速度档位使用中文名称。推理强度标签采用单行文本；首尾标签分别贴齐滑杆内容区左右端点，中间标签按 `NSSlider.rectOfTickMark` 的真实刻度中心定位，不折行，也不按相邻刻度区间居中。外部会话的 `read-model-settings v1` 不返回速度；同连接短暂订阅原会话实时快照，核对 owner、会话和协议版本，优先读取 `latestThreadSettings.serviceTier`，未指定时取最后一个真实轮次的 `params.serviceTierForTurn / serviceTier`。`fast / priority / ultrafast` 显示闪电，显式清除档位不回退旧值；读取结束取消该连接订阅，不新增常驻轮询或模型请求。
- **新版桌面队列**：临时聊天和历史回复框在原会话空闲时可发送。每次主动发送先经 `codex://threads/<id>` 打开目标原会话，桌面端运行中及冷启动共用此入口。跳转成功回调后检查桌面队列；跳转和队列准备共用 60 秒期限，两个入口都能取消。就绪后复核原轮次再提交。提交前只读核对原线程与末轮，确认当前桌面端已打开同一队列。多个客户端可共用该队列；若桌面端以外的进程正打开目标 UUID 的写锁文件，则保留草稿并停止提交。写锁文件不存在或已关闭时可入队。短命令关闭 daemon 自动启动，省略 `--resume`，每次只投递一次。命令成功退出、回执给出队列项 ID 并匹配原线程 UUID 后，即结束本次提交。只清理原入口仍与已提交内容相同的草稿。原会话出现新轮次后，“已排队”提示消失。原观察器提供轮次状态，执行期间禁用普通发送，回到空闲后开放下一条。命令已启动但没有有效回执时保留草稿，显示“检查发送结果”。当前随附 CLI 的 Queue 接口只按线程排队。已观察到目标轮次执行中时，临时输入与历史回复框在操作区独立一行，以系统半粗体和主文字色提示点击「跳转到 Codex」进入原会话插话。
- **旧版通道在桌面端运行中与冷启动时的发送流程**：
  - **桌面端已就绪（热路径）**：若已缓存有效会话设置则直接建立 IPC 连接提交，否则先触发一次原会话路由再连接（单次连接上限 `2s`、重试间隔 `250ms`、总窗口 `20s`）。
  - **桌面端未运行或刚启动不足 10 秒（冷启动路径）**：保存原请求、会话、轮次与原文进入准备态。针对桌面端冷启动账户确认阶段替换初始主窗会清空首窗待发路由的问题，仅在桌面端存活且尚未发现 owner 时，于 `2.5s`、`7.5s`、`14s` 后台静默补投递 `codex://threads/<id>`（`activates = false`），一旦连上或用户点击“取消发送”立即停止。主动准备循环与被动 `5s` 节流的 `refreshSettings` 解耦：单次 `thread-owner-discovery` 上限 `1.5s`、间隔 `250ms`、总窗口 `60s`；等待期间收到目标会话的 `thread-stream-following-status-requested` 或带变更的 `thread-stream-state-changed` 广播时，在同一连接立即重发发现请求，成功后同连接读取模型设置并直接提交。
  - **防重发边界**：真实 `start-turn`／`steer-turn` 发出后若连接中断或回执超时，会话转入 `Unconfirmed`（待确认）并保留原文草稿，不自动重发，也不改由内置 `app-server` 接管。
- **桌面 IPC 套接字（`DesktopSocket`）**：在请求等待与广播监听两条路径上对 `client-discovery-request` 统一应答 `canHandle = false`，其余未知请求返回 `no-handler-for-request`；请求帧 `timeoutMs` 与分片 `poll` 等待严格收敛于当前调用剩余期限。
- **审批与问答**：外部项目问卷由 `DesktopSync` 按当前通信方式呈现。新版气泡引导用户打开出题的原会话，由 Codex 接收回答。旧版普通问卷在气泡内逐题填写或跳过，经 `DesktopQuestionReply` 提交非空答复。人设问卷由独立连接的 `RequestCoordinator` 处理。敏感问题隐藏题面与答案。
  - **新版项目命令审批（开发版实验）**。受信任项目登记 `PermissionRequest` 的 `Bash` Hook 后，Codex 调用同一桌宠可执行文件的 `--codex-permission-request` 入口。桌宠按外部会话和活动轮次匹配，气泡显示原命令、会话目录和审批理由。点击「允许这一次」或「拒绝」，只向这笔请求返回对应决定。点击「转到 Codex」、桌宠不可用或等待超过 110 秒，由 Codex 接续原生审批。问卷、文件修改和 MCP 工具沿用各自的原窗口入口。
  - **启用实验**。构建并启动当前开发版，在桌宠源码目录运行 `python3 scripts/project-approval-hook.py /目标项目目录`（本项目可用 `.`）。脚本向目标项目的 `.codex/hooks.json` 增加一项。用该项目的 Codex CLI 打开 `/hooks`，核对并信任「等待桌宠审批」，再在桌面端打开项目会话。可在同一入口停用。桌宠仅在新版模式监听用户私有临时目录中的本地套接字，双方核对用户及桌宠可执行文件。每笔决定与原 Hook 进程的连接绑定；普通命令、旧版 IPC 和人设会话各走原有流程。[Codex Hooks 官方说明](https://learn.chatgpt.com/docs/hooks#permissionrequest)
  - 审批按钮均无回车或键盘允许快捷键。旧版外部审批解析兼容 `thread-stream-state-changed` v11～v13，校验同源连接和协议版本。提交允许前再次核对 owner、请求 ID、轮次与非空命令详情。
- **公开进展投影与分组（`TaskActivity`）**：
  - 仅提取公开 `reasoning.summary` 与工具结构化字段（`commandActions`、`tool`、`namespace`、`server`、`changes` 等）。多行 shell 命令仅取首行命令与参数并标记省略，单次最多展示 3 条（每条 120 字）。

  - 「消息与提醒 › 气泡内容与任务概览 › 显示哪些消息 › 隐藏工具执行失败提示」（`hideToolFailures`）默认开启，仅过滤单次工具 `failed` 的进展小气泡、组标题文案和失败角标；混合组保留成功操作与其他进展，拒绝／取消／中断仍按实际状态展示。显示层保存完整与过滤后的组摘要供开关即时切换，不修改历史、原始进展或整轮任务结果；整轮失败、审批与问卷沿用原显示规则。关闭「显示工具调用」时收起该关联项并保留原值，设置导入导出及消息页／全部恢复默认值覆盖该键。
  - 图标映射：思考使用 `lightbulb.max`；等待批准／回答使用 `hand.raised`／`questionmark.bubble`；计划项（上限 8192 字）使用 `list.bullet.clipboard`；子代理协作与等待（`collabAgentToolCall`／`collabToolCall`）使用 `figure.and.child.holdinghands`／`figure.child.and.lock`；审查模式使用 `doc.text.magnifyingglass`；网页搜索／打开／页内查找分别使用 `globe`／`network`／`doc.text.magnifyingglass`；MCP 工具按明确 `server + tool` 映射至文档、表格、幻灯片、邮件、日历或代码图标，其余归入 `wrench.and.screwdriver`。
- **重连与终态判定**：重连状态跟踪 `error.willRetry` 与本轮公开重试事件，重试中显示橙色呼吸 `wifi.exclamationmark`，恢复出新进展后显示 2 秒绿色 `wifi`，最终放弃重试显示红色 `wifi.slash`。`CodexErrorMessage` 将常见错误映射为准确中文并保留底层错误详情（区分本机 IPC 断开、网络错误与不同原因的 HTTP 429）。仅真实 `completed` 记为任务完成；用户输入经 `UserInputText` 剥离附件包装后提取纯提问与紧凑文件链接，外部执行中插话按 `userMessage` ID 去重合并并沿用原轮次计时。

<a id="current-history"></a>
### 历史与数据

- **存储格式与容错迁移**：偏好设置使用独立域 `com.bailongpet.appkit.settings.v2`（首次启动定向迁移旧域已知键并保留原数据）。历史库采用 SQLite schema 3（`~/Library/Application Support/BailongPetAppKit/history.sqlite`），首次读取旧版 JSON schema 1／2 时在事务内完成迁移并保留原 JSON 备份；若遇数据库损坏、更高版本 schema 或磁盘写入失败，自动进入只读保护模式并提供原库导出与重新加载，不以空库覆盖用户数据。
- **按需加载与记录冻结**：开启记录历史（默认开启）时，内存仅常驻会话与轮次元数据，正文通过最多 `16` 条／`2 MiB` 的 LRU 缓存按需从 SQLite 读取；历史窗口每页固定展示 `20` 轮，翻页替换渲染结果，关闭窗口时清空正文、TextKit 排版与搜索缓存。关闭记录历史期间冻结磁盘快照，停止写入且重新开启后不补录关闭期间的对话。
- **会话排序、重命名与删除**：会话标题优先同步 `threads.name`（未生成前按 `5s` 节流补查，用户手动重命名后固定保留本地名称直至主动恢复同步），列表按真实最新消息或轮次起止时间倒序排列。工具栏右侧 `trash` 按钮与右键菜单共用无默认回车的删除确认：内置运行中会话先停止任务再在事务内删除记录并登记防回填 ID；外部会话仅移除桌宠侧记录与同步订阅，不影响 Codex 桌面端原会话。
- 内置流式更新只刷新当前会话的可见正文、最近回复与变化的文件统计。`ConversationOrder` 在历史窗口可见时按活动时间排列会话，同一时间按原集合靠后者优先。消息时间变化时只调整该会话的位置；窗口重开时从当前集合恢复顺序及正文。搜索期间重新匹配正在更新的会话。
- **全文搜索与当页补缺**：历史工具栏内置原生搜索框（`⌘F` 聚焦，`⌘G`／`⇧⌘G` 跳转上下处匹配），支持跨会话正文摘要筛选与当页高亮定位（命中折叠文件列表时自动展开）。首次进入或重开历史窗口定位至底端，同会话刷新保持当前滚动位置，显式搜索跳转优先。外部会话缺失早期用户输入文本时，仅对当前可见页按需读取补齐（遵守记录冻结与只读边界）。
- **轮次标题与底栏渲染（`TranscriptRenderer`／`TranscriptActionBar`）**：内置与外部轮次提供 `TurnCompletion` 的身份、终态、结束时间与用量。气泡和历史按各自正文字号创建底栏，历史另传拷贝正文和原会话链接。用户与桌宠发言标题分别前置系统人物图标与 `petAvatarTemplate`，名称与时间使用应用强调色；本轮文件修改摘要在 `turn.finished` 后渲染于正文下方。每轮底栏左侧展示完成状态与真实 `completedAt`（缺失标“未提供”），随后通过现有 `DisclosureControl` 展示紧凑的 `本轮  <数量> Tokens`；汇总不使用明细列宽，数量与单位用不换行空格连接。同一行内利用组间留白对齐标签；Token 胶囊换行后从正文左侧布置完整边框与内边距，明细对齐胶囊文字。展开明细继续用真实 Tab 与 `NSTextTab` 对齐输入／缓存命中／输出列。右侧提供仅复制助手正文的拷贝按钮与“转到 Codex”按钮，宽度不足时按钮另起一行靠右。
- **异常恢复面板（`Recovery`）**：覆盖启动资源检查、历史库读写与首段动画加载异常，提供可滚动的错误详情拷贝、局部重试与新建 Issue 链接，不安装全局信号吞错器，也不在诊断文本中拼接对话正文或凭证信息。

<a id="current-animation"></a>
### 动画与吸边

- **解码管线与无缝交接**：角色动画共 35 段透明 HEVC `.mov`（33 段 `24 fps`、2 段移动素材 `30 fps`），经 `AVAssetReader` 解出 BGRA 帧后由 `CPUFrameConverter`（`vImage`）完成线性光缩放与色彩转换，交由 `SpriteView` 的 `CALayer.contents` 直接呈现 `CGImage`（仅图像身份、绘制区域、几何变换、刘海裁切或屏幕 `backingScale` 实际变化时提交图层属性，关闭 Core Animation 隐式动画）。切换动作时仅取消未完成的后台加载任务并递增 `generation`，旧动作持续供帧，待新动作准备好首帧及约 `250ms` 可播放余量（整段预加载模式则待全段就绪）且代次有效后再原子切换画面与时间轴。按下桌宠期间不暂停选帧，落地动作等待后续指令期间保持末帧。
- **画质、帧率与缓冲参数**：新用户默认采用流式播放、`512×512`（较高）、`12` 帧缓冲（可设 `6～240`，非法输入失焦恢复 `12`）与“满帧”档位。画质提供 `自动`、`原画 720`、`较高 512`、`中 384`、`低 256`（`自动` 按 `角色逻辑尺寸 × 动作 renderScale × 屏幕 backingScale` 选取最小足够档位）；帧率上限提供 `满帧`、`20 FPS`、`15 FPS`（流式限帧在色彩转换前按源 PTS 抽样以节省缩放与遮罩开销，动作总时长不变）。开启“整段动画预加载”（默认关闭）时，缓冲帧数与开头缓存自动收起并保留原值。
- **画质与性能增强项**：
  - **动作平滑过渡**（`animationSmoothTransition`，默认开启）：非同动作且非吸边几何动画交接时，在统一逻辑画布上按 `64×64` 网格采样旧末帧与新首帧 Alpha 加权重合度；重合度 `≥ 90%` 时向图像图层提交 `180ms` `CATransition.fade`（遵守“动态效果”与系统“减少动态效果”）。
  - **孤立杂点清理**（`animationEdgeCleanup`，默认开启）：在生成预乘 RGBA8 后剔除八连通分量内全部像素 `Alpha ≤ 16/255` 且面积不超过阈值（`256／384／512／720` 档对应 `1／2／4／8` 像素）的游离噪点，毗邻主体或柔边的像素逐字节保留。
  - **常用动作开头缓存**（`animationOpeningCache`，默认开启）：对已播放的常用待机、拖拽、落地与额度动作缓存前 `6` 帧图像及 Alpha 命中遮罩，LRU 总上限严格控制在 `24 MiB` 运行内存 (RAM) 以内；命中后即刻满足起播并由后台按相同相位续读后续帧。
  - **轮廓阴影**（`petShadow`，默认关闭）：控制桌宠窗口 `NSWindow.hasShadow` 并在图层更新后刷新透明轮廓阴影（偶发黑点问题列于 TODO 排查）。
- **调度计时与动作权重**：素材选帧使用单次 `Timer` 锚定动作时间轴（容许 `1µs` 浮点误差，回调晚到不顺延下一帧基准）；桌宠可见且已加载动画期间持有单份 `.userInitiatedAllowingIdleSystemSleep` 活动断言，在可见播放期间保持应用活动（不阻止显示器或系统空闲休眠，手动隐藏、全屏自动隐藏、系统睡眠或退出时立即释放）；窗口位移与旋转缩放使用 macOS 14+ `NSView.displayLink` 跟随当前屏幕刷新率，静止或隐藏时立即挂起。随机池默认比例为：普通待机 `4:1`、吸边待机 `7:3`、任务执行中先排除上一动作再按 `35:65` 抽取工作组／待机组；用户可在 `0～12` 之间调节单段动作权重（默认待机保底为 `1`）。仅额度查询加载期间（`quotaLoading`）暂停自主活动；首次启动完成首段加载后播放一次 `01` 问候动作（已有活动任务或打开面板时跳过）。
- **手势识别**。`SpriteView` 接收 AppKit 事件，`PetGestureState` 记录按压、拖动和待执行的松手动作，`PetController` 执行绑定动作、打开菜单和驱动动画。菜单跟踪期间识别的第二次按下只触发一次，随后送达的同一鼠标事件直接结束处理。
- **左右边缘吸边、刘海收纳与多显示器**：
  - 左右边缘吸边与顶部刘海吸边独立开关，露出比例范围均为 `40%～85%`（步进 `5%`，默认 `55%`）；吸边单击松手后由 `PetGestureState` 记录 `250ms` 召回期限，沿用动画调度器到期处理；期限内再次按下即执行绑定的双击动作，吸边拖动直接召回。
  - 刘海位置通过内建显示器 `safeAreaInsets.top` 与左右 `auxiliaryTopLeftArea`／`auxiliaryTopRightArea` 实时计算，拖入顶部 `24pt` 触发区后旋转 `180°` 倒挂贴合；无刘海屏幕自动忽略顶部收纳并保持左右吸边可用。位置记忆始终保存展开态安全坐标（初始默认位于屏幕可用区横向 `85%`、距底边 `23%`）。
  - `preferredDisplay` 为空时允许跨屏自由拖动；指定显示器后将桌宠移动与拖动范围约束在该屏幕内，外接屏断开时临时回退至可用屏幕并在重连后自动归位。
- **性能统计窗口与采集口径（`Diagnostics`）**：默认关闭，仅在窗口打开期间每秒采样并差量刷新界面，关闭窗口即刻停止计时器（支持左上角置顶 Pin 与“拷贝完整诊断”）：
  - **拷贝完整诊断**：成功写入剪贴板后，在统计窗口显示原生对话框，性能图标下的只读富文本框与消息输入框共用圆角底色和留白。正文使用点击时写入剪贴板的同一份快照，从首行开始，可滚动并选择文字。点击强调色“知道了”或按回车关闭。写入失败时按钮显示“拷贝失败”。
  - **版本信息**：桌宠显示 `VERSION` 与构建中记录的 8 位提交号。Codex 桌面端从应用包读取版本与构建号，运行时附 PID。Codex CLI 优先显示桌宠自己的 app-server 握手返回的版本。尚无握手版本时，若选用桌面端随附的 CLI，则从对应安装包的清单读取并标注「安装版本」。
  - **更新 FPS**：统计 `SpriteView` 每秒向图层提交的不同 `CGImage` 帧数（纯几何位移不计入帧率；完整诊断另附含几何更新的图层提交总次数与最长帧间隔）。
  - **CPU**：基于 `getrusage` 进程累计 CPU 时间差分；界面总体占比除以逻辑核心总数，完整诊断附加单核满载 `100%` 基准值。
  - **GPU**：基于 `PROC_PIDCOALITIONINFO`（`coalition_info_resource_usage.gpu_time`）差分，反映当前应用进程组（含子进程）的 GPU 时间占比。
  - **本段动画等帧次数**：流式播放时，到换帧时间却还没有可用新帧，每次连续等待计为 1 次。标签右侧的问号提供悬停说明，完整诊断使用同一名称并列出最长等待时间。
  - **运行内存 (RAM) 与 Swap**：运行内存取 `TASK_VM_INFO.phys_footprint`（完整诊断附 `compressed` 压缩内存及去重后的驻留帧像素字节数；`512×512` 下 12 帧缓冲队列像素与遮罩约占 `15 MiB`，`720×720` 约 `29.7 MiB`）；系统交换空间取 `vm.swapusage`，本进程累计换入量取 `ledger_swapins`。

- **分栏架构与静态搜索（`SettingsPanel`／`SettingsSearch`）**：设置窗口共分 9 个侧栏页面：`通用`、`称呼与个性`、`动作与活动`、`消息与提醒`、`外观`、`高级`、`画质与性能`、`更新`、`关于`。采用原生 `NSSplitViewController` 贯穿侧栏、统一工具栏与原生分组表单（正文区上限 `780pt`，“恢复本页设置为默认值”与红色“恢复全部设置为默认值”固定于侧栏左下角）。首次打开设置时按需构建当前页，重复打开已构建页不重建子树，关闭设置窗口时释放当前页控件与关联资源；`SettingsSearchEntry.all` 纯静态构建分类、分组、标题、前置条件与同义关键词索引，搜索过程不实例化未访问页面，也不触发磁盘扫描或登录项查询。

- **消息主题页的数值按钮**：`SettingsForm.observeValues` 在注册时立即从偏好填充按钮摘要和可见状态。偏好变化时，`refreshAvailability` 重新计算摘要及状态，前置开关关闭时收起已打开的编辑浮层。表单重置时清理回调。

### 额度与用量

- **多套餐识别与额度排版（`QuotaQuery`／`Bubble`）**：
  - 首行标题区分 `ChatGPT 免费用户`（Free）、`ChatGPT 订阅 · <套餐名>` 与 `计费方式 · <名称>`；Business 体系按公开 `planType` 精细区分 `Business Standard`（`team`／`business`）、`Business Premium`（`self_serve_business_prolite`）与 `Business 按量计费`（`self_serve_business_usage_based`），且当 `account/read` 返回具体子档时优先于 `rateLimits` 的粗粒度标记。
  - Free 与 Go 账号仅展示单条 `30 天额度`（无可用重置卡且无点数余额时省略空重置卡行）；Plus、Pro、Business Standard 等多窗口套餐展示 `5 小时额度` 与 `周额度`。额度名称和右侧剩余值共用基准 `13pt` 字号，剩余比例 `≤ 10%` 标橙色、`≤ 5%` 标红色。
  - `QuotaCoordinator` 提供查询结果、缓存时间和手动刷新入口。`QuotaBubbleBody` 排版正文、管理加载与峰谷计时，并向 `Bubble` 报告宽高和展开明细需要显示的区域。`Bubble` 管理窗口、卡片和滚动位置，关闭或替换正文时立即停止正文计时。
  - 额度气泡内说明文字、缓存时间戳、日志副标题及展开明细统一采用高对比正文色 `labelColor`。重置时间采用 `12.5pt` 半粗等宽数字字体，中文日期与时刻紧接显示，如 `2026年11月24日13:41`。通过真实 `\t` 与 `NSTextTab` 对齐右侧倒计时，如 `5天17小时29分钟`，不足一分钟显示 `<1分钟`。气泡最小排版宽度随重置行实测宽度自适应以避免折行。重置卡张数与到期明细下附小字可用点数说明。底栏左侧是原生圆角「订阅管理」菜单按钮，右侧是带 `arrow.clockwise` 图标的强调色「立即刷新」按钮（失败态显示「重试」），两者共用字号和布局高度。
- **可选额度缓存**：`quotaCacheEnabled` 默认关闭；开启后仅在运行内存 (RAM) 缓存最近一次成功结果（`quotaCacheSeconds` 默认 `60s`，范围 `15～300s`，不落盘）。ChatGPT 额度命中前先通过轻量 `account/read(refreshToken: false)` 校验当前账号身份，若账号切换、连接重建、到达任一窗口重置时刻或超过缓存有效期则自动重新请求。第三方 API 视图缓存供应商身份与本机今日 Token 结果，只复用同供应商、同缓存代次、同一天内的成功结果；关闭缓存或点击「立即刷新」会重新扫描日志。缓存命中时界面注明 `缓存 · 更新于 <时间>`。
- **第三方 API 供应商额度窗**：额度查询先通过 `config/read` 读取当前工作区的 `model_provider`。识别到非内置供应商 ID 时，跳过 `account/rateLimits/read`，气泡顶部使用横向 `NSStackView` 按 `centerY` 排列供应商图标与 `当前 API 供应商：<完整名称>`，用量只统计该供应商原始 ID 在本机 `CODEX_HOME/state_5.sqlite` 中对应会话的今日 Token。Kimi 中国站／国际站、智谱 BigModel／Z.AI 与阿里云百炼北京／新加坡使用各自官方控制台入口；区域共用图标，但名称、计费或用量页面不混用。底栏左侧在目录有官方入口时以普通圆角按钮显示带 `arrow.up.right.square` 图标的「打开供应商开放平台」，链接取自供应商目录。未知主机可按已知 provider ID、别名或完整名称回退；三者均未匹配时显示配置名称，未填名称则显示原始 ID，隐藏按钮。右侧正常时显示「立即刷新」，失败时显示「重试」。`openai`、Bedrock 与 Google Cloud 继续使用原有订阅／计费额度窗；供应商读取失败时同样回落原查询，因此不会覆盖 ChatGPT 订阅额度失败提示。运行时供应商图标统一为 `openai-logo.png`、`deepseek-logo.png`、`xai-logo.png`、`mistral-logo.png`、`kimi-logo.png`、`zhipu-logo.png`、`bailian-logo.png`、`openrouter-logo.png`、`groq-logo.png`、`bedrock-logo.png`、`vertexai-logo.png`，文件缺失时不显示图标。
- DeepSeek 作为第三方 API 供应商时，额度气泡在今日 Token 行后补充峰谷定价状态：北京时间工作日 `9:00～12:00`、`14:00～18:00` 为红色高峰时段，其余时间及周末、中国法定节假日为绿色空闲时段；下一时段按 `yyyy-MM-dd HH:mm CST` 显示，下方另起一行显示切换倒计时，超过一天时包含天数。已维护 2026／2027 年国务院放假安排，未知年份显示“时段未提供”。气泡可见期间逐秒更新倒计时文字，峰谷边界或午夜重新排版。更新使用本机时钟，收起或切换气泡时停止计时。
- **Token 用量统计与统一展开控件（`DisclosureControl`）**：
  - **本轮用量**：取会话累计 Token 快照的当轮增量（`cachedInput` 已包含在 `input` 内，不重复累加至 `total`；内置会话监听 `thread/tokenUsage/updated`，外部会话在轮次结束后按日志偏移读取公开 `token_count`）。
  - **今日用量（本机日志）**：查询额度时在后台按本机时区增量扫描当前 `CODEX_HOME` 日志文件（跨日自动归零、自动去重分叉事件，订阅额度命中缓存时仍实时刷新日志增量，第三方视图使用上文的本机用量缓存规则）。
  - **数量单位**：汇总与各明细按各自原始整数判断，只有 `1` 使用 `Token`，`0` 和其他数量使用 `Tokens`，默认使用千位分隔的完整数字。「消息与提醒」的「Token 用量」紧接在「声音」之后，可切换到 K / M / B 或万 / 亿，按最高单位四舍五入保留两位小数，低于最小单位显示完整整数。缓存命中率按缓存输入除以总输入，四舍五入保留一位小数，输入为零时省略百分比。明细按实际标签、数字和单位共用列宽计算。
  - **统一交互控件**：额度弹窗、历史底栏与任务完成气泡底栏全部复用 `DisclosureControl`。三个 Token 入口共用一项展开偏好，默认收起，切换记录和重启应用均沿用上次选择。文件列表也使用该控件，展开状态由各正文独立维护。明细收起时显示向下箭头，展开后显示向上箭头。常态无外框，鼠标悬停文字或箭头的任意位置时绘制整块圆角高亮背景，点击整块区域切换展开／收起，右键支持拷贝汇总文本；展开后的 `输入 / 缓存命中 / 输出` 明细使用独立 TextKit 视图（`SelectableRichText`）与真实 `NSTextTab` 对齐三列并支持自由划选复制。

### 文件与产物

- **Git 悬停图例**：Git 状态胶囊文字截断或仅显示图标时，悬停显示完整分支与操作短标题，以及当前风格的符号图例。图例沿用紧凑状态的颜色。「消息与提醒 › 工作区状态 › Git 状态显示风格」依次提供 bash-git-prompt 符号风格（默认）、Powerlevel10k 符号风格和缩写字母风格。三种风格共用状态条的顺序和排版。bash-git-prompt 状态条形如 `main  ✖2 ●12 ✚37 …9 ⚑3 ↓2 ↑5`，依次显示当前引用、冲突、已暂存、未暂存、未跟踪、贮藏、落后和领先。缩写字母风格依次使用 `C`、`S`、`M`、`?`、`SH`、`↓`、`↑`。选项下方的图例按通用 Git 仓库、GitHub 远端仓库、其他远端仓库的顺序展示实际图标，使用真实 Tab 和 `NSTextTab` 对齐。绿色工作区干净标识与仓库图标同行，bash-git-prompt 使用 `✔`，其余风格使用 `✓`，文件状态、贮藏及上游差异位于下一行。图例为静态说明文本。状态条、详情和图例随选择更新。状态条的工作区名称、详情的分支标题、工作区路径和远端链接同样只在截断时显示悬停提示。
- **Git 操作状态**：Git 详情和辅助功能显示 `变基 (Rebase) 2/5`、`拣选提交 (Cherry-pick) 进行中`、`撤销提交改动 (Revert) 进行中` 或 `当前不在任何分支上 (Detached HEAD)`。Rebase 无步数时显示 `变基 (Rebase) 进行中`。紧凑状态栏用「变基中」「拣选中」「还原中」显示操作，分离 HEAD 时显示标签或短提交号。

### 构建与集成

- **构建入口与增量缓存**：根目录 `build.command` 与 `run-dev.command` 共用 `scripts/swift-environment.sh`、`scripts/swift-sources.sh` 与 `scripts/resource-manifest.json`。脚本根据当前 SDK 自动启用 `full`（27+）、`glass`（26+）或 `plain`（14+）编译条件，并将 `SDKROOT` 透传给主程序与跟随启动 helper 的编译链接流程。从 Git 工作区构建或开发运行时，终端在版本号后显示当前提交号的前 8 位。非 `main` 分支的本地构建将当前提交号写入 App 的 `Info.plist` 或开发程序的内嵌 plist。`run-dev.command` 的增量缓存同时校验源码列表、文件时间戳、SDK 版本、编译器版本、档位参数与本地构建提交号。
- **运行素材**：开发程序从 `Assets/ProviderIcons/` 读取供应商小图标，预检核对文件齐全，构建 App 时复制到 `Contents/Resources/`。脚本按当前检出的 `scripts/resource-manifest.json` 下载素材 ZIP，并将清单要求的动画及配套文件导入 `local-assets/`。

- **正式版更新检查（`Updates`）**：启动自动检查默认关闭。开启后，距上一次手动或自动发起检查已满 `24h` 才在启动时请求。检查时间在发请求前保存，失败、取消和重启均计入间隔；同时间只发起一次检查，失败后等待下次启动或手动操作。检查通过 `URLSession` 沿用系统 HTTP／HTTPS／PAC 代理与 TUN 路由，读取公开仓库 `releases/latest` 并按 SemVer 比较版本（请求超时 `20s`、资源超时 `30s`）。收到限流时保存 GitHub 给出的恢复时间；识别为限流而无有效恢复时间时等待 `60s`。限流期间所有入口暂停请求。手动检查超过 `8s` 显示慢速提示，可取消；失败时展示原因与技术详情。自动检查失败仅记录于设置页，发现新版时显示非抢焦提示并提供「禁用自动更新检查」。
- **登录自启与随 Codex 启动（`Autostart`／`FollowMonitor`）**：仅维护用户主动开启的启动项，应用路径或版本变化时自动更新注册信息，用户从系统设置撤销许可后保持关闭状态不强行重装，运行于 `AppTranslocation` 临时只读路径时拒绝绑定启动项。跟随启动由同架构独立 helper 监听桌面端 Codex／ChatGPT 应用进程生命周期（不监听命令行 `codex`）；后台串行卸载旧服务并注册新服务，遇 `launchd` bootstrap 错误码 `5` 时延迟 `1s` 重试一次。
- **默认工作区与本机数据清理**：默认工作区留空时使用 `~/Library/Application Support/BailongPetAppKit/Workspace`；点击“清理内置工作区”仅将该根目录下的直接子项移入系统废纸篓（不跟随符号链接，不影响聊天历史，有任务运行或发送中时拒绝清理；用户指定自定义目录时隐藏该清理按钮）。设置高级页分别提供“清空磁盘缓存”与“清空本应用的本机数据”两项独立确认操作。

## 0.7.5-dev.5 · 连续播放与起播缓冲

用户复测 dev.4 停顿仍存在。本轮 `tick` 在按下桌宠期间继续选帧，取消 mouseDown／mouseUp 对素材时间轴的暂停补偿；按住未拖动时不自动换动作，几何移动仍遵守原按键状态。隐藏时仍暂停并在显示时恢复时间轴。

`StreamingAnimation.prepareForPlayback` 在加载任务内准备首帧与 capacity 帧后续队列，短片 EOF 提前就绪；准备过程中核对请求身份，失效则取消 reader 并放弃发布。随后沿用统一 publish 切换画面和时间轴，不再首帧一到就切换。旧流在目标准备期间继续供帧；整段预加载仍等待全段完成。没有跨动作常驻缓存、全库预热或额外固定等待时间。起播缓冲为解码较慢的设备留出准备时间，此改动保留为面向老设备的优化方向。用户在 agy 再次运行时使用 dev.6 仍复现停顿，P0 继续定位刷新和供帧瓶颈；M1 Air 的实际收益及 RAM 峰值待实测。

## 0.7.5-dev.4 · 动画加载交接

用户反馈手动随机／指定动画切换会先停住再播放，而自动播放正常；整段预加载未改善。`Decoder.load` 原先调用 `cancel()` 立即停止当前流；现在仅取消待完成 worker 并更新 generation，保留活动流供应旧画面。新片段首帧（流式）或全部帧（整段预加载）就绪后，由统一 publish 在主线程核对 generation，交付画面与时间轴，再停止旧流。过期预备流立即停止；失败保留当前画面并报告加载错误。

`cancel()`、configure 和 close 仍停止当前流。切换期间只重叠当前动画与正在准备的目标动画，不预热整套素材；整段预加载仍需等待目标片段解码完成，旧动画继续显示。吸边召回已有 pending 动作时直接播放目标，不先启动待机解码。默认缓冲、帧率和画质不改；没有加入姿势插值或交叉淡化。实际流畅度、快速连点及运行内存 (RAM) 峰值待用户验收。

手动 `preview` 仅在显隐状态实际变化时调用 `applyVisibility`，避免已可见时重建托盘菜单；先发起 `play`／吸边召回，再调用 `say` 排版气泡。自动入口不经过这段手动显示流程，手动与自动的差异继续按 P0 跟进。

| Infrastructure | 更新、跟随启动、本机存储、恢复与诊断 |

`RequestCoordinator` 拥有审批／问答队列及原生 sheet，回调核对原 Turn 与窗口；结束任务先撤销请求归属。`DesktopHistoryReader` 只做 SQLite 读取，`DesktopSync` 负责投影与提醒；不会借外部观察接口执行内置任务。问题更新同时比较身份与内容，按仍适用的问题 ID 恢复草稿。

历史文件现使用 schema 2，读取 schema 1 时先备份再原子升级；`recordingPolicy` 仍为可选，缺失时按首次启用策略处理。记录开关的冻结身份和外部开始时间边界与正文快照一起原子保存；关闭期间不保存正文，重启后的持续任务也不能回填。关闭／开启会写入策略元数据，正文仍冻结。重复本地会话／轮次 key 在加载时拒绝，原文件保留。

保存使用独立复制的快照，发布给写队列后不再修改；后台编码、原子写入，待写版本合并。失败后暂停，显式重试重新抓取当前允许保存的内容。历史正文仅在窗口显示时构造，未变化的轮次复用 Markdown 渲染；这一实现不等同于已测得性能提升。

构建、开发和本地回归入口共用 `scripts/swift-sources.sh` 的递归清单；开发构建同时比较清单与修改时间。`Tests` 按项目策略仅保留本地，`check-*` 是本地维护入口，缺少夹具时明确报错。当前更改的编译、定向检查与未验证范围记录在本地实施记录，不将旧版本检查当作当前验收。

## 动画与性能

当前 catalog 共 35 段 MOV，保留原动作清单的时长、缩放、偏移和位移参数。待机、第二待机、拖拽、落地采用去杂色及局部描边平滑后的素材：前三段各 96 帧／24 fps／4 秒，落地 48 帧／24 fps／2 秒，720×720。清理副本与原始 PNG 均保留。

性能页“动画效果改善 → 轮廓阴影”暂默认关闭，已有明确保存值保留。开启后使用 AppKit `NSWindow.hasShadow`，在图层状态更新后通过 `invalidateShadow()` 更新透明轮廓。设置持久保存，参与性能页恢复、导入导出及设置搜索；不生成描边位图、不添加帧缓存或刷新定时器。作者基线 `b102e73` 的 `Pet.paintEvent`／`draw_frame` 直接绘制素材，没有运行时描边或发光滤镜；轮廓阴影是可选显示效果，不修改素材内的轮廓线或颜色。dev.4 用户反馈开启时偶发黑点、关闭后消失，具体原因尚未定位。

新用户默认较高 512×512、12 帧后续缓冲、满帧播放，已有保存值保留。画质另有原画 720×720、中 384×384、低 256×256；缓冲可设整数 6～240，输入非法值在结束编辑时恢复 12；素材 FPS 上限可选“满帧 (≥ 24 FPS)”／20／15。满帧按素材 nominalFrameRate 与播放速度调度，当前 33 段为 24 fps、2 段为 30 fps，不插帧。FPS 上限与播放速度独立，时间轴和动作时长不改变。

流式读取在串行后台队列进行，首帧及约 250 ms 可播放余量就绪后交接，按视频 PTS 消费，缓冲满暂停读取。准备期间旧流续播，只准备当前请求；可选开头缓存复用已播放帧，不主动预热。帧图像与 Alpha 命中同步缩放，首帧边界映射到 512 逻辑画布；generation 屏蔽过期任务，退出等待当前解码结束。详细门槛、缓存预算和循环规则见现行动画约束。

“整段动画预加载”默认关闭；开启后完整读取当前动作再播放，同动作循环复用，切换动作重新载入，不预热整个素材库。启用后缓冲和常用动作开头缓存置灰并保留值。设置顺序为画质、帧率上限、缓冲帧数、常用动作开头缓存、整段预加载；具体文案以设置页源码为准。

当前默认 12 帧队列在 512×512 下，RGBA 图像及 Alpha 平面按紧密排列估算约 15 MiB（720×720 时约 29.7 MiB）；首帧、当前帧、在途帧及可选开头缓存另计。这只是像素估算，不是进程总运行内存 (RAM)。用户曾反馈旧版 dev.7 约 280～300 MB，不沿用为当前版本结果。

## 性能统计口径与窗口

统计默认关闭，只在窗口启用时采集。独立 NSWindow 默认位于主屏左上角，显示 Dock 图标，可最小化并从 Dock／菜单召回。左下角 pin 开关控制 floating／normal，默认置顶并记忆；右侧关闭与拷贝按钮同排。红灯和关闭按钮销毁窗口并停止采样，绿灯禁用。设置中开关窗口保留设置 key window。

固定布局实时显示更新 FPS、CPU 总体、运行内存 (RAM)、应用组 GPU 和本段缺帧等待次数，每秒只更新变化的值。“拷贝完整诊断”在点击时生成文本，包含动画耗时、帧缓冲、CPU 单核基准、压缩及 Swap、硬件和会话连接；系统 Swap、GPU 型号与桌面进程信息在生成报告时读取。

- 更新 FPS：SpriteView 提交给图层的不同 CGImage 数；几何更新不重复计入，HI／LO 为本次开启极值，包含暂停和隐藏。完整诊断另计包括几何变化的图层更新次数、最长图像更新间隔及请求到图层提交耗时；均为应用提交口径，不代表屏幕实际呈现。
- CPU：getrusage 进程累计 CPU 时间差分；总体占比除以逻辑核心数，单核基准以一个核心满载为 100%，允许超过 100%。不是最忙核心读数，也不对大小核算力加权。
- GPU：PROC_PIDCOALITIONINFO 与 coalition_info_resource_usage 的 gpu_time 差分，显示应用资源组口径，包括同组子进程；不等同于整机 GPU 饱和度。失败显示错误，不伪报零。
- 运行内存 (RAM)：TASK_VM_INFO.phys_footprint；压缩量单独读取 compressed。驻留帧按图像及 Alpha 字节估算，重复引用去重；系统图形／解码资源不包含在帧估算中。
- Swap：系统交换空间来自 vm.swapusage；本进程累计换入来自 ledger_swapins，并按返回结构长度判断字段是否存在。正数表明曾换入，零不排除已换出但未读回；不提供无法确定的本进程当前磁盘换出量。字节口径依据 [Apple XNU 实现](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/vm/vm_compressor.c)。
- 当前无应用自建的动画磁盘缓存，不把素材文件或会话文件算作缓存。
- 完整诊断分别列出 Codex／ChatGPT 桌面进程及只读同步状态、桌宠自身 CLI app-server 状态／PID／路径。

## 气泡材质与设置交互

### 气泡动态效果（dev.7）

外观／消息窗口新增 bubbleMotion 开关，默认 true，纳入恢复本页、恢复全部与偏好导入导出。BubbleMotion 统一消息气泡与临时输入窗的逻辑显示状态、实时目标位置、160ms 淡入+4pt ease-out 位移、120ms 淡出和 140ms 高度过渡。仅短过渡期间使用主线程 common-mode Timer；结束或销毁时停止，无持续动画轮询。快速重开从当前透明度接续，没有延迟 orderOut 回调。跟随移动直接改目标位置，尺寸与透明度不重新排队；正文更新不重播出现动画。

BubbleBackgroundView 的正文永久固定在根视图，玻璃位于底层、普通背景覆盖层位于中间。切换时仅过渡普通覆盖层的透明度，玻璃在普通背景完全覆盖后才隐藏；160ms 结束后停计时器。滑块调玻璃不透明度仍即时更新，不重置过渡。不截取窗口快照，不缩放文字或重挂输入框。

关闭动态效果立即落到当前目标状态；减少动态效果时仅保留短淡入淡出，取消位移、高度与材质动画。不改变独立 typingEffect 和盲文加载提示。编译不代表动画真机验收，禁止自行截图或启动视觉测试。

### 设置操作区对齐（dev.8）

alignedRow 统一固定操作区 trailing；compactControl 递归收紧组合控件，NSStackView 使用 fill、零 edgeInsets，并按 fittingSize 固定无显式宽度的操作组。避免外框右对齐而内部 gravity 仍留白。已有固定宽度沿用，普通数值／缓冲滑块组均为 272pt，玻璃双图标滑块组为 244pt；只读值在自身框内右对齐。标题和说明左对齐，色点名称居中，单选组内部左对齐；不把所有文字一概右对齐。分类单元格清除 tooltip，侧栏工具栏按钮显式保留 tooltip，辅助功能名称保留。

### 素材播放与几何动画解耦（dev.9）

configureAnimationTimer 仅按 animationFPS 驱动素材选帧及动作调度。吸边收起／展开和自主移动在 updateGeometry 内由 NSView.displayLink 驱动；macOS 14 起可用，回调同步视图所在屏幕，跨屏无需硬编码刷新率。弱 target 避免控制器循环引用，静止和隐藏时暂停，close/deinit 时 invalidate。

保留作者 300ms 吸边缓动及移动素材的 moveStartMs/moveStopMs 时间轴。显示刷新复用当前 CGImage，不调用 selectFrame；结束时保留动作切换，并将自主移动落到终点。拖拽仍由鼠标事件立即定位。素材帧率上限独立于刷新率；统计中的 FPS 由不同图像计数，draws 允许同一图像多次绘制。

本地 SDK NSView.h 的 NSDisplayLink 分类明确 API_AVAILABLE(macos(14.0)) 与视图屏幕同步行为。未运行窗口、截图或真机刷新率验收。

### 窗口、提示与任务时长（dev.10）

设置 show 设置 regular activation policy、注册窗口菜单并还原最小化状态；Dock 加设置入口，reopen 优先还原最小化窗口。关闭统计不强制切回 accessory。AppDelegate 区分显式完整退出和界面关闭：⌘Q 走 closeInterface，Dock terminate 在非明确退出时取消终止；sheet／模态窗口按取消处理，保留审批默认拒绝及补充输入取消的原行为。完整退出继续回收任务进程；系统 willPowerOff、SIGTERM/SIGINT 保留正常退出，不以此阻止系统结束会话。

WindowFade 只管桌宠 alpha，不干预位置；首帧准备后才开始出生淡入，全屏避让与手动隐藏共用 160ms／120ms，关闭 bubbleMotion 立即完成过渡。设置独立注释使用 note 工厂（11pt、secondaryLabelColor），group 遇注释不插前置分隔线；行内 detail 同样保持次级灰色。自定义色点符号为 paintpalette，关闭气泡用辅助功能名代替 tooltip。

Bubble 接收任务开始时间及任务 key，右上角 stopwatch 与单宽数字显示 MM:SS／H:MM:SS，最小 00:00。内置任务用 Turn.date（提交时，含启动等待）；外部任务使用本地 thread_turns.started_at，经现有每秒同步发现，非远端零延迟查询。气泡计时每秒本地计算，更新同一任务不重启计时器；匹配任务结束、气泡隐藏或销毁停止刷新，不写入历史。开始时间缺失的外部任务不伪造时长。

文字流水仅用于 animated heading 的正文：1.2 秒亮带扫过、2.8 秒停顿，使用渐变文字透明度，盲文和空格排除；盲文仍约 10 次／秒切换并跟随强调色。文字效果遵守 bubbleMotion 和 Reduce Motion，不重置任务时长。

素材帧率选项精简为“满帧 (≥ 24 FPS)”／20／15。当前资源通过 AVFoundation 元数据读取确认：33 段 24 fps，move03left／move03right 两段 30 fps。Animation 保留 nominalFrameRate；满帧调度为源帧率乘播放速度，20／15 为上限。用户偏好和旧导入文件的 24／30 迁移到 full。几何 display link 与素材调度继续独立。

任务计时排版（dev.12）：关闭按钮、标题首行、计时组同一行；秒表紧贴实际文字宽度，间距 3pt（随气泡比例缩放），计时整体右对齐。标题按剩余宽度换行，不截断或缩字；跨小时重排，正文与计时不重叠。任务结束后保留最终用时并停止计时器，completed 使用 systemGreen，failed／interrupted／cancelled 使用 systemRed。内置任务按完成事件到达时冻结；外部任务优先使用 thread_turns.completed_at，未提供时用观察到结束的时间。

文字流水方向：浅色模式保留深色底字，扫过时降低文字不透明度形成浅色带；深色模式为灰字被亮带扫过。禁止浅底界面把浅字作为常态、深字作为扫过效果。

## 新鲜额度查询与重置卡（dev.12）

dev.13 结果正文修正：DesktopSync 使用 TaskOutcome 分别生成完成／失败／中断标题和正文。禁止以 value.title 回填空回复，该字段是会话标题，常来自用户首条输入。错误 JSON 只提取 message；没有错误说明或最终回复时直接显示对应状态说明。历史会话标题照常保存，不删改用户记录。

QuotaQuery 每次新建，不跨查询保存额度。连接仍复用，但先发 account/rateLimits/read，再并行 account/read(refreshToken:false)；额度响应直接展示，账号晚到只补同次套餐信息，不重新播放出现动画或重置气泡倒计时。serial 与 quotaActive 继续拦截关闭气泡、换任务后的旧回调。失败显示错误，不用旧成功结果回退。

用户允许本轮测试：真实只读请求测时、协议数据回归及临时 AppKit 窗口几何／计时断言；未发起模型任务，没有截图或视觉审美验收。具体测时与运行记录保存在本地实施记录。

消息气泡底部左右等宽：转到 Codex／查看记录详情，间隔 8pt 随比例缩放。左侧使用官方 codex://threads/<thread-id>，以历史 Conversation.threadID 关联；无 ID 的示例或未建立会话打开桌面端，不创建新任务。右侧继续打开桌宠历史。官方入口：[会话深链接](https://learn.chatgpt.com/docs/reference/commands#deep-links)。技术错误气泡仍用技术详情与重试。强调色色点及自定义颜色面板行名称统一“自定义”。

## 称呼与台词编辑

SettingsTemplateField 和独立的 SettingsTemplateEditor 仅用于“称呼与个性”，其余输入框仍使用系统编辑器。菜单保留剪切／拷贝／粘贴／全选；台词及特定称呼另有三种变量插入，名字字段没有分隔线或插入项；菜单文字用 Tab 和统一 NSTextTab 停靠点对齐。编辑时通过 NSLayoutManager 临时属性着色，非编辑时使用属性文本显示，保存／拷贝仍为纯文本；输入法组字期间不截断。指代符采用适配深浅模式的蓝／紫／橙文字与淡色底。

名字和称呼 20 字，问候与各类台词 120 字；计数器位于输入框右侧，与清空按钮同排；普通文字按 Swift Character 计数，每个变量整体计 1 字，达到上限为红色。既有值不在启动时截断，重新编辑时执行新上限，导入使用相同上限。“互动台词”的恢复默认仅清空 customLines；整页／全部恢复与导入导出包含任务进展、成功、失败、中断、等待回答、等待批准和额度查询七项台词。空状态台词使用内置默认值。示例台词将主人与角色名转换成对应指代符，实际气泡预览再展开。

任务执行中、成功、失败、中断／取消和额度查询中分别通过 PetPreferences.statusLine／taskResultLine 读取；只替换标题，不改模型正文、错误详情或历史任务文本。长标题高度由原生 cell 测量，计时文字与第一行原生基线对齐，标题区域右边界始终停在计时区域左侧。

## 待处理请求气泡

TaskAttention 将内置 requestUserInput 与外部公开 questions 映射到等待回答；命令／文件修改审批映射到等待批准。两项模板属于称呼与个性，遵循 120 字、指代符高亮、恢复默认与导入导出。等待时暂停文字流水，elapsed 继续由任务开始时间计算，气泡不自动消失。敏感请求保留整行高亮“转到 Codex”；内置审批召回原生请求窗口，外部审批在气泡窗查看详情并明确提交决定，保留 Codex 跳转入口。非敏感选择题的直接提交见下方 dev.17 说明。

内置普通进展更新不覆盖正在等待的请求；结束回答／批准时清理同会话的等待气泡，审批默认拒绝及取消输入后停止任务保留。外部同步以公开问题、item 等待状态和 turn 等待状态区分两类，读取 userMessage 时仅由 SQL 投影回答关联的问题标题，排除答案值。跨轮次按 questionItemId 移除已回答问题，后续普通进展不提前清除未回答问题，任务终态清除等待状态。

isSecret 标记的请求不在气泡显示问题、选项或输入值，包含敏感提问的外部 agentMessage 正文不进入同步结果。桌宠 Turn 仅新增可选的 sensitiveQuestionNotice／sensitiveInputNotice：分别显示“（已隐藏{桌宠名}的敏感信息提问）”与“（已隐藏{用户名}的敏感信息输入）”，旧历史无需迁移；只有提交后才记输入。输入值仅用于原生请求回复，不进入这些历史字段，外部答案值不由观察器读取。该规则依据明确的敏感请求标记，不将普通消息按关键词猜测为敏感输入，也不修改 Codex 原始记录。

### dev.17 问题交互与本机存储

非敏感问题使用原生单选、其他回答和补充输入；草稿仅存在当前请求内存中，关闭气泡保留，回答或请求结束后销毁。窗口允许拉伸并重排，右上角仍是累计用时，不设自动提交／消失倒计时。内置任务经原连接回复；桌面端由 DesktopQuestionReply 连接当前用户的 `.codex/ipc/ipc.sock`，按桌面端 v1 owner discovery / follower steer 路由发送带 questionItemId 的原格式回答。此接口依据本机已安装桌面端代码核对，不宣称为稳定公开 API；不改 Codex 配置、数据库或凭证，不自动重试提交。失败保留输入并提供原有转到 Codex 入口。已回答检测跨轮次只投影问题 ID，不读取答案。

高级页统计本应用数据目录、专用缓存目录和偏好文件，默认任务文件夹单列，百分比以三项总量为基数；文件大小统计跳过符号链接。清空本机数据只重置桌宠历史／同步副本及应用设置，保留任务文件、Codex 原始记录、凭证和跟随启动项。同步清除时间水位防止旧副本立即回填；清空磁盘缓存不冒称释放动画帧缓冲的运行内存 (RAM)。危险确认无默认回车操作。

### dev.18 问卷分页

QuestionForm 一次呈现一道题，导航保留输入，最后通过原会话提交非空回答。跳过仅改变本地表单，不写入空答案或伪造用户回复。多行文本共用 MessageEditor，发送与换行遵守 sendShortcut，提供灰色快捷键提示；左右 5pt 内缩为焦点边框留出空间。

### dev.19 气泡位置

BubblePlacement.swift 统一消息气泡和临时回复窗的屏幕定位：屏幕可用区域内缩 8pt，以角色可见边界计算上下左右候选，当前方向无遮挡则保留，否则选择无遮挡候选；空间不足时选择最小遮挡并约束在屏幕内。气泡大小变化触发重排，普通正文更新且原位置仍安全时保留位置。拖拽、吸边与动画切换不关闭气泡；临时回复窗不把桌宠左键事件当作外部点击收起。

### dev.20 个性设置与变量迁移

TemplateSyntax.swift 将 {称呼}→{特定称呼}、{名字}→{用户名}、{桌宠}→{桌宠名}；仅限 customAddress、各 Template 键及 customLines。启动用独立迁移标记只执行一次，导入文件每次规范化；解析继续识别旧别名，用户名／桌宠名、历史与原始正文不迁移。每个变量作为一个计数单位，截断保持变量完整，替换结果不递归解析。

### 气泡显示优先级（0.5.0-dev.11）

BubbleCard.priority 区分 companion、message、request：attentionAction 为待处理请求，显式任务概览及无会话的互动提示为 companion，其余为消息。Bubble.present 先保存及更新卡片，再决定是否切换；更高优先级可替换当前卡片，同级普通消息不抢阅读位置，互动提示之间仍可更新。翻页停留于真实消息、存在问卷表单或正在提交时不自动切至其他卡片；翻回概览不阻挡新的任务消息。同 ID 流式更新不受切卡限制，后台卡片继续保存。额度与独立预览保持既有直接展示入口。

### 内置会话复用与同级任务切卡（0.5.0-dev.19）

协议依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server) 的 start/resume、loaded threads、thread/closed 与 turn/start；本机 ChatGPT.app 内置 codex 的协议类型导出确认 ThreadResumeParams、TurnStartParams 和 ThreadLoadedListResponse。导出位于忽略的 .build/protocol-dev19，仅生成接口文件，没有启动服务或发送任务。原作 app/chat_backend.py 的 run 也仅在 session 未 initialized 时创建／恢复会话。官方资料未解释截图具体 writer 的所属进程，不将代码中的重复恢复路径直接等同于已证明的锁持有原因。

Bubble.present 对未手动翻阅的同级任务消息继续切换；请求仍保持更高优先级。显式内置发送通过 selectCard 选中新任务卡，用户之前翻阅旧结果不再让新任务停留后台；保留未答问题／提交中表单，正常翻阅历史时仍不被后台消息切走。所有独立消息仍保存，未合并或删除旧卡。

## 0.6.0 当前开发实现

### 数据来源与状态选取

本机桌面端协议来源为已安装 ChatGPT.app 26.1027.30824 的 app.asar（early-bootstrap-339-aea964a206c655e4.js、early-bootstrap-916-2f6483d5bfd826f1.js、app-initial 资源）。DesktopApprovalReader 复用 DesktopSocket，订阅 thread-stream-following-changed v1，接收 thread-stream-state-changed v11 的 snapshot／patches；这是当前安装版本的实现依据，不是稳定公开 API。

观察连接仅订阅执行中会话，不成为 writer；每 5 秒快照校准，增量核对 sourceClientId／baseRevision，超过 8 秒未确认的快照丢弃。DesktopRuntimeProjection 投影 requests、turns 和 turnHistory.history.entitiesByKey 中的请求身份与公开活动字段，不保留 reasoning.content、工具输出、用户输入或会话设置。停止观察关闭连接，删除本地会话不停止 Codex 任务。

TaskActivity 统一内置事件与外部实时／历史数据：思考读取公开 summary；读取、列目录和搜索读取 commandActions 的 type／name／path／query；调用工具显示 namespace／server 与 tool；文件修改显示路径。命令缺少结构化动作时显示原命令，不分析工具 arguments 推测含义。运行中工具优先于旧摘要，同阶段空摘要不覆盖已有摘要；摘要 item 完成不等于轮次结束，不切换为“思考摘要”占位标题。真实轮次完成后停止进展。

DesktopSync 每 0.2 秒调度实时接收，历史数据库最多每秒读取一次，标题仍每 5 秒补查；已获得的实时投影可清除旧数据库活动。概览每 0.2 秒刷新内存状态，无展示变化不重刷历史正文。以上是源码调度参数，端到端更新延迟尚未实测。

### 展示、尺寸与设置

任务概览中，进展位于执行中任务标题上方一行；MarqueeProgressField 以 Core Animation 重复同句，仅超宽时启用，末尾以同字体三个空格间距衔接下一遍首字、速度 28pt/s，内容改变重置，同内容保留相位。减少动态效果／关闭动态效果时静态渐隐；隐藏停动画，不随动画查库。进展不生成记录卡片，正文消息与待处理请求仍按真实消息／请求身份保存。

Pet 持有独立 progressToast 非激活 Bubble，自动小气泡默认开启，思考或工具活动变化自动触发，优先桌宠上方，默认停留 2 秒（1～10 秒）。同内容不重复弹出，变化原地更新并重计时；与主气泡重叠、待处理请求、手动翻阅、临时输入或额度展示时让位。结束、停止观察、隐藏及退出清理。自动宽度按文字在 280～360pt 基准内扩展，整窗高度最多 180pt，均随气泡比例缩放，再受屏幕可用区域限制；标题单行并保留完整悬停，超出正文滚动。上限也优先于短气泡自定义宽高比，不限制审批和普通消息。

外观“气泡形状”提供 bubbleAspectEnabled（默认关闭）和 bubbleAspectRatio（0.6～3.0，初始 1.5）。开启后消息／进展气泡按宽高比布局，操作区最低尺寸及屏幕边界优先；问卷手动尺寸优先，额度继续按内容排版。设置变更刷新既有气泡，不改变任务或历史。

消息与提醒中，“气泡卡片与任务概览”紧接“显示哪些消息”；showThinkingProgress、showToolProgress 默认开启，progressToastEnabled 默认开启。“进展小气泡停留时间”在“停留时间”组最后，思考与工具共用时长。个性页 taskThinkingTemplate／taskToolTemplate 默认分别为“{桌宠名}正在思考”／“{桌宠名}正在调用工具”。这些设置接入原有搜索、导入导出和恢复。

### 气泡窗内直接审批

DesktopApproval 在明确点击后新建 socket，先 thread-owner-discovery，再读取 owner 最新快照，核对原请求 ID、method、turnId、操作详情和执行中轮次。命令／文件修改调用 thread-follower-command-approval-decision v1／thread-follower-file-approval-decision v1，决定为 accept／decline；权限调用 thread-follower-permissions-request-approval-response v1，scope 为 turn。发送后读取快照确认请求移除；缺少操作详情不能同意，超时／不完整回执保留待确认且不自动重发。ApprovalPresentation 绑定原表单，迟到回执不更改后来请求。

气泡窗先展示审批理由，再展示命令、工作目录等完整可滚动详情。DesktopApproval.detailSections 按显式顺序保存原文字段，details 仍用于提交前内容核对。ApprovalText 渲染理由中的 Markdown 代码块；独立命令直接交给 CodeBlockRendering（shell），结构化权限等使用 JSON 代码框，原命令不经过 Markdown 解析。底部保留等宽拒绝／允许按钮及转到 Codex。拒绝使用淡红底、动态红字和 xmark，允许使用淡绿底、动态绿字和 checkmark；文字和图标同时区分动作，深浅模式采用系统语义色与 labelColor 混合提高文字对比。按钮无默认操作、快捷键、键盘焦点或键盘激活，保留辅助功能显式操作。隐藏／关闭不提交决定。

消息页“气泡窗审批按钮顺序”使用 approvalButtonOrder：rejectLeft（默认）或 allowLeft，仅交换两个按钮位置，不改动作。内置原生审批对话框默认拒绝，Codex 自身界面不受此选项影响。敏感问题仍跳转 Codex，不展示答案。

### 原生代码块

MarkdownText 读取 Foundation 的 codeBlock 语义，CodeBlockRendering 使用一列单个 RoundedCodeBlock（NSTextTableBlock 子类）承载语言头与连续代码正文，通过公开 drawBackground 绘制整块圆角普通背景与细边界；原生按钮仅提供完整复制。基础词法着色覆盖常见语言的关键词、字符串、注释、数字和函数名，未知语言按纯文本显示。代码保持在文本存储中，缩进、空行、选择、历史搜索及未闭合围栏的流式正文保留；没有远程依赖或代码执行。

气泡／历史／审批共用 StreamingTextView，按语言头文字位置摆放右侧复制按钮，代码在窄窗口自动换行。按用户反馈移除放大按钮及 CodeBlockWindow 独立窗口。

### 订阅管理与重置边界

额度底部 SubscriptionManagementButton 使用原生文字按钮和 NSMenu。所有 ChatGPT 套餐（含 Free、未识别套餐）显示“订阅管理”：个人网页为 https://chatgpt.com/settings/billing，另有 Google Play subscriptions 与 Apple account/subscriptions；组织提供工作区网页。API、AWS、Google Cloud 显示“计费管理”并跳转对应控制台。套餐与额度来自本次返回，名称与网页入口由本应用映射；不读取购买渠道、网页账号、凭证、续费或自动续费日期。额度名称、数值及管理按钮不提供 hover，其余界面保持完整提示。

按用户决定暂不增加“上次实际重置日期”。自然周期重置、官方直接赠送重置和重置卡分别处理。[公开额度协议](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt) 的 resetsAt 表示下次重置；当前安装桌面端对应 used_percent／limit_window_seconds／reset_at，另有重置卡接口，未找到上次实际重置时间或原因的字段。不能用下一次时间减周期、重置卡发放时间或本机观察时间冒充实际重置日期。

### 本机文件链接召回访达

0.6.1 修正窗口枚举：先读取 `id of every Finder window` 为本地列表，后续通过 `Finder window id` 查询目标目录和恢复窗口。不得直接遍历未求值的 `Finder windows`：循环变量的 `item N` 引用会交给 Finder 解析为窗口内文件，读取其 `target` 会报 -1728。本机只读对照已复现旧路径报错、确认 ID 路径正确匹配目录；用户于 2026-11-02 对修复版文件链接测试反馈“通过”。AppleScript 循环引用语义见 [Apple 文档](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_control_statements.html)。

MessageFileLink 保留路径、主机、相对目录及行号解析。用户明确点击本机文件链接时，通过 Finder 公开自动化接口复用目标目录窗口、取消该窗口最小化并选中文件；没有对应窗口才创建目标目录窗口。不打开 Finder.app、不发送 reopen、不恢复全部窗口，.app 仅定位不运行。首次由系统请求控制访达授权，拒绝或失败明确提示，不假报恢复成功；不申请辅助功能。脚本固定，文件路径通过参数传入。 用户确认采用带系统自动化授权的精确恢复方案。采用 Finder 字典的 target／collapsed／index／selection／frontmost，不依赖激活进程推测最小化恢复。

### 设置条目与搜索索引同步

## 文件引用与修改摘要（0.7.0-dev.2）

## 历史按需存储与分页（0.7.2-rc.2）

## 外部实时投影的正文范围（0.7.2-rc.3）

### 待机选择与原作对照（2026-11-07）

消息修复阶段没有修改动作切换，后续源码对照发现 Swift 原有选择规则不完全等同原作者 v0.5.1 / b102e73 的 `app/pet.py:idle`。两边均在片段结束时选择下一段，普通待机池为 idle／idle2；连续播放不同待机动作是两边都有的行为。

| 场景 | 原作者 | 调整前 Swift |
| --- | --- | --- |
| 普通待机 | 固定 4:1，可连续重复 | 默认基础权重 4:1；启用避免重复时，上一动作权重乘 0.35；支持自定义权重与收藏 |
| 执行任务 | 工作／待机组按 35:65 选择，先排除上一动作，再在组内均匀选择 | 工作／待机组按 35:65 选择，组内使用通用权重，上一动作只降权，不排除 |
| 吸边 | 固定 7:3 | 使用通用待机权重及避免重复设置 |

默认未自定义、未收藏时，Swift 普通待机播放 idle 后，下段 idle2 概率为 1/(4×0.35+1)，约 42%；原作为 20%。任务中 Swift 允许同一待机动作连续重复，原作排除该动作。这些差异来自 `PetController.idle()` 与 `PetPreferences.choose()`，并非本次气泡或素材试用改动。随后用户授权同步，当前已改为下述规则。


当前默认选择与原作一致：普通待机 4:1、吸边 7:3，任务候选先排除上一动作与关闭动作，两个非空组按工作／待机 35:65 选择，只有一个组时直接选择该组，组内默认均匀；开场后也按任务组内规则选工作动作。`AnimationSelection` 区分普通、吸边、任务与其他随机场景。保留 Swift 的手动频率及偏爱，相对原默认频率按比例调整场景权重；若用户只启用当前这一段，继续默认待机。减少重复只作用于其他随机互动、额外动作与移动，不再改变普通待机或吸边比例。

### Codex 重连状态与中文错误

内置 TaskMessageAccumulator 接收 error.error 与外层 willRetry；CodexConnectionProgress 临时保存本轮连接状态，优先于普通工具进展。外部 DesktopRuntimeProjection 仅追加公开错误字段 message／willRetry／errorInfo，DesktopApprovalReader 按会话及轮次记录状态；正文和原始推理内容仍不投影。模型正文／公开摘要的增量只用于确认恢复，不额外留存正文。同批增量按错误与恢复的先后判定，首次快照已有错误之后的模型进展时不重播旧重连。

重连使用 wifi.exclamationmark 与橙色“正在重新连接 N/M…”，N/M 只从原消息提取，未提供次数则省略。恢复需收到真实模型进展，wifi 与绿色“连接已恢复，继续处理。”保留约 2 秒，再显示普通进展。网络错误停止重试使用 wifi.slash 与红色“重新连接失败，Codex 已停止重试。”，最终气泡下方为“检查你的网络或节点环境。”。重试不改变任务执行状态，最终失败由轮次终态确认，秒表不重置。主气泡有本轮内容时只更新进展；没有时复用本轮 connection-status 卡片，不按每次重试增加卡片，不抢问卷、审批与翻阅中的卡片。

TaskActivityAppearance 使用语义橙／绿／红，呼吸仅对图标添加 Core Animation 透明度动画，不增加计时器；隐藏时移除，关闭 bubbleMotion 或启用减少动态效果时静态。普通短进展小气泡布局不变，连接状态使用主气泡与概览。连接状态不拼入助手正文、工具步骤或历史，也不因纯显示变化额外保存历史。

CodexErrorMessage 优先读取结构化 codexErrorInfo／errorInfo／code／type，并识别明确的错误原文。覆盖模型与当前连接方式不匹配、模型无访问权限、订阅额度、API 余额／预算、会话预算、限流、身份验证、服务繁忙、上下文超限、请求／附件设置、权限及已有 writer。HTTP 429 不直接推断余额或订阅额度耗尽；未知错误显示中文通用说明，原始错误保留在技术详情与历史。内置协议连接断开单独提示桌宠未能继续接收状态，不宣告 Codex 已停止上游重试；外部观察失败继续使用现有同步错误入口。

错误协议参考：[Codex App Server 的 Errors](https://learn.chatgpt.com/docs/app-server#errors)、[官方 Codex 协议 schema](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/ThreadListResponse.json)。本轮未编译、未运行真实网络故障或请求，显示与事件接入待用户实机验收。
