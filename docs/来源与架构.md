# 来源与架构

## 当前分支技术栈

`codex/native-hevc-alpha` 的完整桌宠版本为 `0.3.0-dev.3`，最低目标 macOS 14。该分支待用户 review，尚未合并 main；以下描述当前源码实现，运行验收范围另列。

| 层次 | 当前实现 | 主要入口 |
|---|---|---|
| 语言与构建 | Swift，Apple Command Line Tools 的 swiftc，分别编译 arm64 / x86_64；无 Python/PySide6 运行依赖 | scripts/build.sh、scripts/run-dev.sh |
| 桌面界面 | AppKit 的 NSPanel / NSWindow、原生菜单、文本、设置、历史与审批界面 | Pet.swift、NativeUI.swift、Settings.swift、ChatUI.swift |
| 完整桌宠动画 | HEVC with Alpha MOV → AVFoundation AVAssetReader 的 BGRA 像素缓冲 → Core Image Lanczos 缩放 → 512×512 预乘 RGBA CGImage；原生视图逐帧显示 | Resources.swift、Pet.swift |
| 素材准备 | FFmpeg 离线读取 VP9 alpha 并编码 ProRes 4444，再由系统 avconvert 编码和封装透明 HEVC；生成后检查原生首帧解码 | Tools/NativeHEVC/AssetInfo.swift、scripts/prepare-native-assets.sh |
| 内置 Codex 任务 | Foundation Process / Pipe 启动本机 codex app-server，以 stdio JSON 行协议通信；独立处理审批、输入、停止和终态 | Codex.swift、ChatController.swift |
| 外部任务观察 | 系统 SQLite 库以只读方式读取桌面任务公开字段，与内置任务生命周期分开 | DesktopSync.swift |
| 设置与历史 | UserDefaults 偏好、带 schemaVersion 的 JSON 历史；默认数据目录 ~/Library/Application Support/BailongPetAppKit | Preferences.swift、History.swift、Resources.swift |
| 跟随启动 | 同架构 BailongFollow.app、AppKit NSWorkspace 通知与 2 秒刷新、用户主动注册的 LaunchAgent | FollowMonitor.swift、Autostart.swift、Tools/FollowHelper/main.swift |
| 独立动画预览 | AVQueuePlayer / AVPlayerLooper / AVPlayerLayer；独立版本 0.3.0-dev.2 和包标识，不承担桌宠交互 | Tools/NativeHEVC/Preview.swift、Tools/NativeHEVC/VERSION |

完整应用链接 AppKit、AVFoundation、Core Image 和系统 SQLite，包内包含透明 MOV、声音、图标与同架构 helper，不携带 FFmpeg、原 WebM、ProRes 中间文件或用户数据。FFmpeg 按素材准备主机架构选择，与应用交叉编译的目标架构无关。

完整素材输出为 `local-assets/native-hevc/catalog`；完整应用输出为 `dist/native-hevc/<VERSION>/<架构>/白龙娘桌宠MacOS-Swift版.app`，与三动作独立预览分开。原 WebM 在本地保留，素材准备遇到既有输出目录会停止，不覆盖已 review 的素材。

解码保留整段帧缓存、首帧回调和基础动作预热；显示与透明命中使用同一帧，首帧边界用于吸边。非固定缓存的 192 MiB 预算不含全部常驻及在途帧，不能当作进程内存上限，也不代表改成了流式播放。取消通过 generation 与 AVAssetReader.cancelReading 阻止过期回调，退出等待本进程内解码工作结束。

### 当前验证范围

本地实施记录已记载：35 个动作完成原生首帧解码、清单参数静态对照；两架构完整应用编译和本地签名通过，主程序与 helper 架构匹配。用户已确认 Apple Silicon 独立预览可播放。完整桌宠交互、跟随启动系统级行为以及 Intel 真机仍待 review，不能由预览成功或交叉编译通过推定。当前文档核对未重复构建、启动应用或进行视觉测试。

## 明确的 Mac 选择

- Swift + AppKit 从零实现；不是将旧 Python 界面包一层 Swift。不存在 Python/PySide6 运行时。
- 原生 NSPanel/NSWindow、菜单栏、材质、文本和审批窗口。视图坐标与窗口坐标在边界转换，Retina 不重复放大布局。
- 第一阶段保留原 WebM 和随包 FFmpeg。当前 0.3.0 分支将运行素材转换为 HEVC with Alpha，使用系统 AVFoundation 解码及 Core Image 缩放；原 WebM 保留在本地。后台按需解码并缓存，先显示首帧；非固定帧缓存预算仍为 192 MiB，总内存包括基础动作、当前动画和在途帧，不宣称本次已减少常驻帧内存。
- 移动参考作者算法，保持整条路径方向；休闲在动作开始时按偏好设下一次期限（默认 15 秒），在片段边界切换。移动结束有 10 秒冷却。
- 吸边拖出后直接待机是用户指定差异。任务开场先 work01，再进入常规工作；成功时庆祝，失败/中断不庆祝。
- 多任务以活动集合协调，不照搬单一 task_active 布尔值。
- 历史使用新目录与显式 schemaVersion，不直接迁移旧工程历史。公开外部记录只能转成草稿，不能冒称完整分叉。
- 不复制作者每 2 秒写诊断文件的流程。不运行 SHA-256、截图或自动视觉检查。

## 资源来源及分发边界

动画：现有 `bailong-desktop-pet-mac/local-assets/windows-v0.5.1/outputs/白龙桌宠素材`，来自作者 v0.5.1 发布素材。图标沿用该工程按默认待机首帧生成的 ICNS；声音及来源说明取作者 app/sounds。

FFmpeg：imageio-ffmpeg 0.6.0 分发的 ffmpeg-macos-aarch64-v7.1 与 ffmpeg-macos-x86_64-v7.1（[PyPI 0.6.0](https://pypi.org/project/imageio-ffmpeg/0.6.0/)）。0.2.x 曾随包携带；当前 0.3.0 分支仅在构建主机离线使用，不附带于应用。资源、二进制和 .app 均在 .gitignore 中。

透明 HEVC 由原 WebM 经带 alpha 的 ProRes 4444 中间文件，再用 macOS avconvert 的 PresetHEVCHighestQualityWithAlpha 预设生成；不宣称无损。原清单的动作时长、位移时间窗、偏移、大小及台词沿用，仅替换运行文件路径。实现依据：[Apple HEVC Video with Alpha](https://developer.apple.com/videos/play/wwdc2019/506/)。

跟随启动使用独立同架构 helper 和用户主动注册的 LaunchAgent。按 com.openai.codex / com.openai.chat、PID 与启动时间识别桌面应用，手动退出只抑制当前运行周期；不会更改 Codex 配置，也不识别 CLI。AppTranslocation 临时路径拒绝注册，旧配置由用户从固定位置打开完整应用后在设置中修复／更新。此处“不识别 CLI”只限定跟随启动，内置任务仍使用 codex app-server。

作者仓库当前未指定开源许可证，动画也没有额外再分发授权。本工程独立维护，不新增或宣称对原素材的许可证。上游及素材授权尚未确认，相关许可材料仍待整理。

## 历史：0.2.0 架构与验证范围

以下记录当时的 WebM / FFmpeg 路线与发布阶段，不描述当前原生 HEVC 分支的包内容、关于页或远端可见性。

支持分开构建 arm64 与 x86_64 应用，最低目标 macOS 14。每包只携带对应架构解码器；关于页面按编译目标显示架构。Intel 交叉编译及静态架构检查不等于 Intel 真机运行验收。两包仅本地 ad-hoc 签名，没有公证或 GitHub Release。素材与二进制仍不进入 Git。

当时 x86_64 FFmpeg 二进制的构建参数包含 `--enable-gpl --enable-version3 --enable-nonfree`，二进制内 libav* 许可字符串为 `nonfree and unredistributable`。Intel 关于页单独说明该事实，不沿用 arm64 的 GPL-2.0-or-later 文案。当时 Intel 包仅本地使用；若分发携带该解码器的旧路线应用，需先替换解码器并核对其依赖许可。当前原生分支不再将其放入应用包。

用户授权取消 Tests 追踪、版本升级、双架构构建、本地提交及远端推送，并将 ZIP 上传到现有私有仓库的 Release。该操作不变更仓库可见性，也不表示原作素材或 Intel 解码器获得公开分发授权。

本版包括产品名称范围修复、文本选择范围调整和 README 补充说明。两份应用均采用本地 ad-hoc 签名，没有 Apple 公证；Intel 未经实机测试。当时 Intel FFmpeg 包含 --enable-nonfree，关于页保留实际许可状态，不作为可公开转发的软件包。

许可证暂为本地待审方案，未添加覆盖整个项目的 MIT 声明。正式公开发行仍需落实上游授权及可分发解码器和相关许可材料。
