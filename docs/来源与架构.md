`TranscriptRenderer` 在用户正文和桌宠标题之间补齐空行，分隔符使用正文样式，避免继承末尾链接或行内代码属性。用户与桌宠标题均使用 AppAccent 与 semibold，前置用户系统图标与 petAvatarTemplate；主题色变化继续通过现有缓存失效与刷新路径更新显示，不修改历史原文。

每轮结尾显示实际 completedAt 与完成／失败／中断／停止状态，时间缺失明确显示未提供；缓存签名包含 completedAt 和会话 threadID。TranscriptActions 作为显示层属性，为正文预留独立按钮行，MessageTextView 按 TextKit 实际行位置放置原生 TranscriptActionBar，随正文更新／翻页／释放清理。拷贝复用 CopyFeedback，只取本轮助手回复及错误说明；Codex 按钮复用 AppIcons.openAI 和 openConversation，沿用真实线程身份。

`ModelSelectorContent` 分离目标尺寸测量和正文排版，内容变化重新请求弹窗尺寸，`viewDidLayout` 按最终视口重排。推理标题、档位标签按可用宽度测量高度，标签按相邻刻度中点划分区域；屏幕限制下沿用纵向滚动。`ChatComposer` 将状态移至模型下方独立整行，`ComposerStatusView` 使用只读可选择的 `AppTextView`，先按实际宽度测量，再将可见高度限制为 96pt，完整正文通过滚动阅读。

本轮只做 Swift 语法解析与差异检查，未构建或运行。旧会话 owner 查询失败与此次布局修正分开：`DesktopReply.connect` 先查询 `thread-owner-discovery`，获得持有者后读取模型设置；`refreshSettings(force:true)` 只重试此流程，不加载会话、不接管 writer。

## 0.7.5-dev.5 · 连续播放与起播缓冲

用户复测 dev.4 停顿仍存在。本轮 `tick` 在按下桌宠期间继续选帧，取消 mouseDown／mouseUp 对素材时间轴的暂停补偿；按住未拖动时不自动换动作，几何移动仍遵守原按键状态。隐藏时仍暂停并在显示时恢复时间轴。

`StreamingAnimation.prepareForPlayback` 在加载任务内准备首帧与 capacity 帧后续队列，短片 EOF 提前就绪；准备过程中核对请求身份，失效则取消 reader 并放弃发布。随后沿用统一 publish 切换画面和时间轴，不再首帧一到就切换。旧流在目标准备期间继续供帧；整段预加载仍等待全段完成。没有跨动作常驻缓存、全库预热或额外固定等待时间。起播缓冲为解码较慢的设备留出准备时间，此改动保留为面向老设备的优化方向。用户在 agy 再次运行时使用 dev.6 仍复现停顿，P0 继续定位刷新和供帧瓶颈；M1 Air 的实际收益及 RAM 峰值待实测。

## 0.7.5-dev.4 · 动画加载交接

用户反馈手动随机／指定动画切换会先停住再播放，而自动播放正常；整段预加载未改善。`Decoder.load` 原先调用 `cancel()` 立即停止当前流；现在仅取消待完成 worker 并更新 generation，保留活动流供应旧画面。新片段首帧（流式）或全部帧（整段预加载）就绪后，由统一 publish 在主线程核对 generation，交付画面与时间轴，再停止旧流。过期预备流立即停止；失败保留当前画面并报告加载错误。

`cancel()`、configure 和 close 仍停止当前流。切换期间只重叠当前动画与正在准备的目标动画，不预热整套素材；整段预加载仍需等待目标片段解码完成，旧动画继续显示。吸边召回已有 pending 动作时直接播放目标，不先启动待机解码。默认缓冲、帧率和画质不改；没有加入姿势插值或交叉淡化。实际流畅度、快速连点及运行内存 (RAM) 峰值待用户验收。

手动 `preview` 仅在显隐状态实际变化时调用 `applyVisibility`，避免已可见时重建托盘菜单；先发起 `play`／吸边召回，再调用 `say` 排版气泡。自动入口不经过这段手动显示流程，手动与自动的差异继续按 P0 跟进。

当前候选版本为 **0.7.5-rc.1**。当前结构见“当前实现”，共用组件见“当前气泡与复用规则”“文件引用与修改摘要”；各版本段落保留对应改动及验证状态。同一行为以较新版本说明为准；旧段落保留实现演进，不用于恢复已移除的打字机或锁顶逻辑。

## 当前实现

本项目[GitHub 仓库](https://github.com/Joseph-Blue/bailong-desktop-pet-mac-swift)已公开。当前正式版本为 0.7.4，发布标签为 白龙桌宠Swiftv0.7.4。最低 macOS 14，正式发布提供 Apple Silicon 完整应用，Intel 提供 0.7.4 社区测试包，尚未经过 Intel Mac 实机验收。

0.7.3 开发线新增 Rosetta 启动提示（0.7.2 发布包不含此功能）：Intel 主程序启动时通过 `sysctl.proc_translated` 检测 Rosetta 转译，命中后提示改用 Apple Silicon 包，并提供打开最新正式发布页后退出、继续运行 Intel 版、退出三个操作。检测不按 macOS 版本或 CPU 名称猜测；Intel 原生及 arm64 原生运行不提示。更新检查仍只比较最新正式 Release 的版本号，不检查架构附件、不自动安装；两个架构共用发布说明、设置和历史。旧于 macOS 26 的系统固定使用普通消息材质，材质单选置灰，玻璃子选项隐藏。

## 源码职责与边界

源码位于 `Sources/BailongPet`，保持一个 Swift target：

| 目录 | 职责 |
| --- | --- |
| App | 应用启动、菜单、退出生命周期和图标 |
| Pet | 素材解码、动画、桌宠交互及几何运动 |
| Conversation | 内置任务编排、历史保存、搜索与终态 |
| Codex | app-server 协议、请求协调器、只读数据库投影、桌面答案 IPC 和额度 |
| UI | 气泡、历史与输入窗口、共享控件、文字渲染和展示模型 |
| Settings | 偏好、设置窗口、字段控件和变量模板 |
| Infrastructure | 更新、跟随启动、本机存储、恢复与诊断 |

`RequestCoordinator` 拥有审批／问答队列及原生 sheet，回调核对原 Turn 与窗口；结束任务先撤销请求归属。`DesktopHistoryReader` 只做 SQLite 读取，`DesktopSync` 负责投影与提醒；不会借外部观察接口执行内置任务。问题更新同时比较身份与内容，按仍适用的问题 ID 恢复草稿。

历史文件现使用 schema 2，读取 schema 1 时先备份再原子升级；`recordingPolicy` 仍为可选，缺失时按首次启用策略处理。记录开关的冻结身份和外部开始时间边界与正文快照一起原子保存；关闭期间不保存正文，重启后的持续任务也不能回填。关闭／开启会写入策略元数据，正文仍冻结。重复本地会话／轮次 key 在加载时拒绝，原文件保留。

保存使用独立复制的快照，发布给写队列后不再修改；后台编码、原子写入，待写版本合并。失败后暂停，显式重试重新抓取当前允许保存的内容。历史正文仅在窗口显示时构造，未变化的轮次复用 Markdown 渲染；这一实现不等同于已测得性能提升。

构建、开发和本地回归入口共用 `scripts/swift-sources.sh` 的递归清单；开发构建同时比较清单与修改时间。`Tests` 按项目策略仅保留本地，`check-*` 是本地维护入口，缺少夹具时明确报错。当前更改的编译、定向检查与未验证范围记录在本地实施记录，不将旧版本检查当作当前验收。

## 设置与历史界面

设置为贯穿侧栏与表单两栏；历史为贯穿会话侧栏与右侧阅读／输入两栏。使用 NSSplitViewController、NSSplitViewItem、NSToolbar 和跟随分栏的 NSTrackingSeparatorToolbarItem；侧栏可收起及调整宽度，内容从 safe area 下方开始。移除内嵌圆角侧栏、阅读区外框和自绘宽分隔带，保留输入框的边界。设置同类选项采用区外标题、浅底圆角分组及组内分隔线；分组承载语义，不包裹整个内容区。材质集中在原生侧栏与窗口工具栏。

设置表单最大 780pt，分类标题进入工具栏，恢复本页／全部操作固定在侧栏左下角；历史输入区仅占会话列，高度按文本在 76～160pt 范围调整。侧栏显示来源图标与单行截断标题，选中态区分活动／非活动窗口；路径正文仅显示文件夹名，完整路径保留在悬停提示中。原生图标按钮保留命令名称，可访问性标签区分本地与同步记录。

设计参考用户提供的 [macos-golden-gate-design](https://github.com/gambadio/macos-golden-gate-design) 及截图；API 依据 Apple 的 [NSSplitViewController](https://developer.apple.com/documentation/appkit/nssplitviewcontroller)、[NSTrackingSeparatorToolbarItem](https://developer.apple.com/documentation/appkit/nstrackingseparatortoolbaritem) 与本机 macOS 27 SDK。保持 macOS 14 最低构建目标，分栏不引入 macOS 27 专属调用；气泡玻璃以 macOS 26 可用性分支隔离。未读取 Figma 节点，未进行视觉、深浅色或无障碍运行验收。

## 动画与性能

当前 catalog 共 35 段 MOV，保留原动作清单的时长、缩放、偏移和位移参数。待机、第二待机、拖拽、落地采用去杂色及局部描边平滑后的素材：前三段各 96 帧／24 fps／4 秒，落地 48 帧／24 fps／2 秒，720×720。清理副本与原始 PNG 均保留。

外观页“桌宠轮廓 → 轮廓阴影”默认开启，开启后使用 AppKit `NSWindow.hasShadow`，在现有帧绘制后通过 `invalidateShadow()` 更新透明轮廓。设置持久保存，参与外观页恢复、导入导出及设置搜索；不生成描边位图、不添加帧缓存或刷新定时器。作者基线 `b102e73` 的 `Pet.paintEvent`／`draw_frame` 直接绘制素材，没有运行时描边或发光滤镜；轮廓阴影是可选显示效果，不修改素材内的轮廓线或颜色。阴影外观与系统合成开销尚未进行运行验收。

新用户默认较高 512×512、12 帧后续缓冲、满帧播放，已有保存值保留。画质另有原画 720×720、中 384×384、低 256×256；缓冲可设整数 6～240，输入非法值在结束编辑时恢复 12；素材 FPS 上限可选“满帧 (≥ 24 FPS)”／20／15。满帧按素材 nominalFrameRate 与播放速度调度，当前 33 段为 24 fps、2 段为 30 fps，不插帧。FPS 上限与播放速度独立，时间轴和动作时长不改变。

流式读取在串行后台队列进行，首帧完成后开始播放，按视频 PTS 消费，缓冲满暂停读取。保留首帧、当前帧及一个在途帧；容量不跨动作预读。帧图像与 Alpha 命中同步缩放，首帧边界映射到 512 逻辑画布，菜单栏裁剪映射回实际像素。generation 屏蔽过期任务，循环回绕的 epoch 丢弃旧循环结果，退出等待当前解码结束。

“整段动画预加载”默认关闭；开启后完整读取当前动作再播放，同动作循环复用，切换动作重新载入，不预热整个素材库。启用后缓冲整行置灰，关闭恢复保存值。说明固定为“不推荐，会显著增加运行内存 (RAM) 占用。”设置顺序为画质、帧率上限、缓冲帧数、整段预加载。

原画 720×720 下 24 帧 RGBA 图像及 Alpha 平面按紧密排列估算约 59.3 MiB（512×512 时约 30 MiB），这只是像素估算，不是进程总运行内存 (RAM)。用户曾反馈 dev.7 约 280～300 MB，该值属于旧版 256×256 整段解码实测，不沿用为当前版本结果。

## 性能统计口径与窗口

统计默认关闭，只在窗口启用时采集。独立 NSWindow 默认位于主屏左上角，显示 Dock 图标，可最小化并从 Dock／菜单召回。左下角 pin 开关控制 floating／normal，默认置顶并记忆；右侧关闭与拷贝按钮同排。红灯和关闭按钮销毁窗口并停止采样，绿灯禁用。设置中开关窗口保留设置 key window；不设置自定义悬停说明，高度按内容收紧。

- FPS：SpriteView.draw 完成后的不同画面数，重复绘制不重复计入；每秒采样，保留 60 点，HI／LO 为本次开启极值，包含暂停和隐藏。不是显示器扫描刷新率。
- CPU：getrusage 进程累计 CPU 时间差分；总体占比除以逻辑核心数，单核基准以一个核心满载为 100%，允许超过 100%。不是最忙核心读数，也不对大小核算力加权。
- GPU：PROC_PIDCOALITIONINFO 与 coalition_info_resource_usage 的 gpu_time 差分，显示应用资源组口径，包括同组子进程；不等同于整机 GPU 饱和度。失败显示错误，不伪报零。
- 运行内存 (RAM)：TASK_VM_INFO.phys_footprint；压缩量单独读取 compressed。驻留帧按图像及 Alpha 字节估算，重复引用去重；系统图形／解码资源不包含在帧估算中。
- Swap：系统交换空间来自 vm.swapusage；本进程累计换入来自 ledger_swapins，并按返回结构长度判断字段是否存在。正数表明曾换入，零不排除已换出但未读回；不提供无法确定的本进程当前磁盘换出量。字节口径依据 [Apple XNU 实现](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/vm/vm_compressor.c)。
- 当前无应用自建的动画磁盘缓存，不把素材文件或会话文件算作缓存。
- 分开显示 Codex／ChatGPT 桌面进程及只读同步状态、桌宠自身 CLI app-server 状态／PID／路径；连接不等同于登录或配额有效。

任务计时排版（dev.12）：关闭按钮、标题首行、计时组同一行；秒表紧贴实际文字宽度，间距 3pt（随气泡比例缩放），计时整体右对齐。标题按剩余宽度换行，不截断或缩字；跨小时重排，正文与计时不重叠。任务结束后保留最终用时并停止计时器，completed 使用 systemGreen，failed／interrupted／cancelled 使用 systemRed。内置任务按完成事件到达时冻结；外部任务优先使用 thread_turns.completed_at，未提供时用观察到结束的时间。

文字流水方向：浅色模式保留深色底字，扫过时降低文字不透明度形成浅色带；深色模式为灰字被亮带扫过。禁止浅底界面把浅字作为常态、深字作为扫过效果。

## 待处理请求气泡

TaskAttention 将内置 requestUserInput 与外部公开 questions 映射到等待回答；命令／文件修改审批映射到等待批准。两项模板属于称呼与个性，遵循 120 字、指代符高亮、恢复默认与导入导出。等待时暂停文字流水，elapsed 继续由任务开始时间计算，气泡不自动消失。敏感请求保留整行高亮“转到 Codex”；内置审批召回原生请求窗口，外部审批在气泡窗查看详情并明确提交决定，保留 Codex 跳转入口。非敏感选择题的直接提交见下方 dev.17 说明。

内置普通进展更新不覆盖正在等待的请求；结束回答／批准时清理同会话的等待气泡，审批默认拒绝及取消输入后停止任务保留。外部同步以公开问题、item 等待状态和 turn 等待状态区分两类，读取 userMessage 时仅由 SQL 投影回答关联的问题标题，排除答案值。跨轮次按 questionItemId 移除已回答问题，后续普通进展不提前清除未回答问题，任务终态清除等待状态。

isSecret 标记的请求不在气泡显示问题、选项或输入值，包含敏感提问的外部 agentMessage 正文不进入同步结果。桌宠 Turn 仅新增可选的 sensitiveQuestionNotice／sensitiveInputNotice：分别显示“（已隐藏{桌宠名}的敏感信息提问）”与“（已隐藏{用户名}的敏感信息输入）”，旧历史无需迁移；只有提交后才记输入。输入值仅用于原生请求回复，不进入这些历史字段，外部答案值不由观察器读取。该规则依据明确的敏感请求标记，不将普通消息按关键词猜测为敏感输入，也不修改 Codex 原始记录。

### dev.17 问题交互与本机存储

非敏感问题使用原生单选、其他回答和补充输入；草稿仅存在当前请求内存中，关闭气泡保留，回答或请求结束后销毁。窗口允许拉伸并重排，右上角仍是累计用时，不设自动提交／消失倒计时。内置任务经原连接回复；桌面端由 DesktopQuestionReply 连接当前用户的 `.codex/ipc/ipc.sock`，按桌面端 v1 owner discovery / follower steer 路由发送带 questionItemId 的原格式回答。此接口依据本机已安装桌面端代码核对，不宣称为稳定公开 API；不改 Codex 配置、数据库或凭证，不自动重试提交。失败保留输入并提供原有转到 Codex 入口。已回答检测跨轮次只投影问题 ID，不读取答案。

- `DesktopReply.swift` 与问卷回送共用 `DesktopSocket` 帧传输。本机桌面端 26.1027.30824 / 22943 的安装包中，`thread-owner-discovery` 为 v1，普通回复 `thread-follower-start-turn` 为 v2，问卷 `thread-follower-steer-turn` 为 v1。普通回复显式继承线程设置并关闭自动消息接纳分流；不传桌宠人格、模型或沙箱覆盖值。内部 IPC 不属于稳定公开接口。
- `DesktopHistoryReader.requireEndedConversation` 在发送前重新只读核对原会话、最新轮次及终态。无处理端时要求先打开原会话；无法确认发送结果时保留草稿并要求用户检查，不自动重发。发送成功按真实 turn ID 与 DesktopSync 合并，外部任务继续由 Codex 管理审批和执行。此阶段不提供执行中追加或排队。
- ChatInterface 两个输入区按会话分别保存内存草稿；外部输入显示原会话目标和继承设置提示。切换会话不改变已发请求的目标，回调只清理原输入区相符的草稿。
- BubbleCard 保存近期展示内容和回调、问卷草稿及布局状态；同一任务用会话／任务 key／开始时间更新，新消息不抢走已显示的卡片。导航单独位于原等宽按钮上方，单卡隐藏箭头和页码。普通卡片保留最多 20 条，正在阅读或等待处理的卡片不被容量裁掉；额度与预览继续独立显示。
- BubbleTaskList 使用原生平面行，台词下分执行中与最近 5 条结束任务，整行使用官方 codex://threads 跳转。盲文 10Hz，仅在显示时运行；任务状态每秒读取内存投影，结束时间保存在 Turn.completedAt 并遵守历史冻结策略。TaskTiming.elapsed 共用 MM:SS／H:MM:SS 格式，成功绿色、失败或中断红色；旧记录缺少结束时间不推造用时。
- 静态与编译验证不等同于真机同步。普通消息实际进入原会话、桌面端显示与回复回流、双方同时提交时的状态竞态，以及深浅色／缩放／问卷卡片交互，留待用户手动验收。

“消息与提醒”管理 bubbleCardLimit（5～100，默认 20）、recentTaskCount（1～20，默认 5）、showTaskOverview（默认开启）；纳入页恢复、全部恢复及导入导出，数量须为整数。卡片保留量只管本次运行的内存展示，不删除 conversations.json。当前阅读及等待处理卡片不被容量裁掉。

DesktopReply 支持 start / steer 分流：已结束发送下一轮，执行中调用本机 thread-follower-steer-turn v1；等待审批／回答不作为普通插话。发送前重新读最新轮次和状态，插话回执须属于原轮次。明确插话追加到该轮本地输入记录，不覆盖原输入、不生成假新轮次。start 与 steer 都不携带模型、思考或权限覆盖；桌面端决定原会话执行设置。两处输入框通过 thread-follower-read-model-settings v1 只读显示会话设置，仅可见时每 5 秒读取，原始错误可查看。该标签是会话设置投影；正在执行任务的模型由 Codex 当前轮次管理。

本轮仍只构建，未对原会话实际发送或插话；并发结束／切轮、模型设置刷新、滚动条视觉避让、箭头连续点击和倒计时交互待用户手动验收。

## 0.6.0 当前开发实现

### 数据来源与状态选取

本机桌面端协议来源为已安装 ChatGPT.app 26.1027.30824 的 app.asar（early-bootstrap-339-aea964a206c655e4.js、early-bootstrap-916-2f6483d5bfd826f1.js、app-initial 资源）。DesktopApprovalReader 复用 DesktopSocket，订阅 thread-stream-following-changed v1，接收 thread-stream-state-changed v11 的 snapshot／patches；这是当前安装版本的实现依据，不是稳定公开 API。

观察连接仅订阅执行中会话，不成为 writer；每 5 秒快照校准，增量核对 sourceClientId／baseRevision，超过 8 秒未确认的快照丢弃。DesktopRuntimeProjection 投影 requests、turns 和 turnHistory.history.entitiesByKey 中的请求身份与公开活动字段，不保留 reasoning.content、工具输出、用户输入或会话设置。停止观察关闭连接，删除本地会话不停止 Codex 任务。

TaskActivity 统一内置事件与外部实时／历史数据：思考读取公开 summary；读取、列目录和搜索读取 commandActions 的 type／name／path／query；调用工具显示 namespace／server 与 tool；文件修改显示路径。命令缺少结构化动作时显示原命令，不分析工具 arguments 推测含义。运行中工具优先于旧摘要，同阶段空摘要不覆盖已有摘要；摘要 item 完成不等于轮次结束，不切换为“思考摘要”占位标题。真实轮次完成后停止进展。

DesktopSync 每 0.2 秒调度实时接收，历史数据库最多每秒读取一次，标题仍每 5 秒补查；已获得的实时投影可清除旧数据库活动。概览每 0.2 秒刷新内存状态，无展示变化不重刷历史正文。以上是源码调度参数，端到端更新延迟尚未实测。

### 展示、尺寸与设置

任务概览中，进展位于执行中任务标题上方一行；MarqueeProgressField 以 Core Animation 重复同句，仅超宽时启用，末尾以同字体三个空格间距衔接下一遍首字、速度 28pt/s，内容改变重置，同内容保留相位。减少动态效果／关闭动态效果时静态渐隐；隐藏停动画，不随动画查库。进展不生成记录卡片，正文消息与待处理请求仍按真实消息／请求身份保存。

Pet 持有独立 progressToast 非激活 Bubble，自动小气泡默认开启，思考或工具活动变化自动触发，优先桌宠上方，默认停留 2 秒（1～10 秒）。同内容不重复弹出，变化原地更新并重计时；与主气泡重叠、待处理请求、手动翻阅、临时输入或额度展示时让位。结束、停止观察、隐藏及退出清理。自动宽度按文字在 280～360pt 基准内扩展，整窗高度最多 180pt，均随气泡比例缩放，再受屏幕可用区域限制；标题单行并保留完整悬停，超出正文滚动。上限也优先于短气泡自定义宽高比，不限制审批和普通消息。

外观“气泡形状”提供 bubbleAspectEnabled（默认关闭）和 bubbleAspectRatio（0.6～3.0，初始 1.5）。开启后消息／进展气泡按宽高比布局，操作区最低尺寸及屏幕边界优先；问卷手动尺寸优先，额度继续按内容排版。设置变更刷新既有气泡，不改变任务或历史。

消息与提醒中，“气泡卡片与任务概览”紧接“显示哪些消息”；showThinkingProgress、showToolProgress 默认开启，progressToastEnabled 默认开启。“进展小气泡停留时间”在“停留时间”组最后，思考与工具共用时长。个性页 taskThinkingTemplate／taskToolTemplate 默认分别为“{桌宠名}正在思考”／“{桌宠名}正在调用工具”。这些设置接入原有搜索、导入导出和恢复。

### 气泡窗内直接审批

DesktopApproval 在明确点击后新建 socket，先 thread-owner-discovery，再读取 owner 最新快照，核对原请求 ID、method、turnId、操作详情和执行中轮次。命令／文件修改调用 thread-follower-command-approval-decision v1／thread-follower-file-approval-decision v1，决定为 accept／decline；权限调用 thread-follower-permissions-request-approval-response v1，scope 为 turn。发送后读取快照确认请求移除；缺少操作详情不能同意，超时／不完整回执保留待确认且不自动重发。ApprovalPresentation 绑定原表单，迟到回执不更改后来请求。

气泡窗先展示审批理由，再展示命令、工作目录等完整可滚动详情。DesktopApproval.detailSections 按显式顺序保存原文字段，details 仍用于提交前内容核对。ApprovalText 渲染理由中的 Markdown 代码块；独立命令直接交给 CodeBlockRendering（shell），结构化权限等使用 JSON 代码框，原命令不经过 Markdown 解析。底部保留等宽拒绝／允许按钮及转到 Codex。拒绝使用淡红底、动态红字和 xmark，允许使用淡绿底、动态绿字和 checkmark；文字和图标同时区分动作，深浅模式采用系统语义色与 labelColor 混合提高文字对比。按钮无默认操作、快捷键、键盘焦点或键盘激活，保留辅助功能显式操作。隐藏／关闭不提交决定。

消息页“气泡窗审批按钮顺序”使用 approvalButtonOrder：rejectLeft（默认）或 allowLeft，仅交换两个按钮位置，不改动作。内置原生审批对话框默认拒绝，Codex 自身界面不受此选项影响。敏感问题仍跳转 Codex，不展示答案。

### 原生代码块

MarkdownText 读取 Foundation 的 codeBlock 语义，CodeBlockRendering 使用一列单个 RoundedCodeBlock（NSTextTableBlock 子类）承载语言头与连续代码正文，通过公开 drawBackground 绘制整块圆角普通背景与细边界；原生按钮仅提供完整复制。基础词法着色覆盖常见语言的关键词、字符串、注释、数字和函数名，未知语言按纯文本显示。代码保持在文本存储中，缩进、空行、选择、历史搜索及未闭合围栏的流式正文保留；没有远程依赖或代码执行。

### 本机文件链接召回访达

0.6.1 修正窗口枚举：先读取 `id of every Finder window` 为本地列表，后续通过 `Finder window id` 查询目标目录和恢复窗口。不得直接遍历未求值的 `Finder windows`：循环变量的 `item N` 引用会交给 Finder 解析为窗口内文件，读取其 `target` 会报 -1728。本机只读对照已复现旧路径报错、确认 ID 路径正确匹配目录；用户于 2026-11-02 对修复版文件链接测试反馈“通过”。AppleScript 循环引用语义见 [Apple 文档](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_control_statements.html)。

MessageFileLink 保留路径、主机、相对目录及行号解析。用户明确点击本机文件链接时，通过 Finder 公开自动化接口复用目标目录窗口、取消该窗口最小化并选中文件；没有对应窗口才创建目标目录窗口。不打开 Finder.app、不发送 reopen、不恢复全部窗口，.app 仅定位不运行。首次由系统请求控制访达授权，拒绝或失败明确提示，不假报恢复成功；不申请辅助功能。脚本固定，文件路径通过参数传入。 用户确认采用带系统自动化授权的精确恢复方案。采用 Finder 字典的 target／collapsed／index／selection／frontmost，不依赖激活进程推测最小化恢复。

### 设置条目与搜索索引同步

## 历史按需存储与分页（0.7.2-rc.2）

`HistoryBody.swift` 使用系统 SQLite3 管理本应用 `history.sqlite`：`history_index` 保存 schema 3 的元数据／录制策略，`history_bodies` 保存按版本标识的正文。旧 `conversations.json` 仅在首次迁移读取，原样保留为迁移前备份；新记录写入 SQLite。原文件导出使用 SQLite backup 接口；旧 JSON 读取失败时仍导出旧 JSON。

### 待机选择与原作对照（2026-11-07）

消息修复阶段没有修改动作切换，后续源码对照发现 Swift 原有选择规则不完全等同原作者 v0.5.1 / b102e73 的 `app/pet.py:idle`。两边均在片段结束时选择下一段，普通待机池为 idle／idle2；连续播放不同待机动作是两边都有的行为。

| 场景 | 原作者 | 调整前 Swift |
| --- | --- | --- |
| 普通待机 | 固定 4:1，可连续重复 | 默认基础权重 4:1；启用避免重复时，上一动作权重乘 0.35；支持自定义权重与收藏 |
| 执行任务 | 工作／待机组按 35:65 选择，先排除上一动作，再在组内均匀选择 | 工作／待机组按 35:65 选择，组内使用通用权重，上一动作只降权，不排除 |
| 吸边 | 固定 7:3 | 使用通用待机权重及避免重复设置 |

默认未自定义、未收藏时，Swift 普通待机播放 idle 后，下段 idle2 概率为 1/(4×0.35+1)，约 42%；原作为 20%。任务中 Swift 允许同一待机动作连续重复，原作排除该动作。这些差异来自 `PetController.idle()` 与 `PetPreferences.choose()`，并非本次气泡或素材试用改动。随后用户授权同步，当前已改为下述规则。


当前默认选择与原作一致：普通待机 4:1、吸边 7:3，任务候选先排除上一动作与关闭动作，两个非空组按工作／待机 35:65 选择，只有一个组时直接选择该组，组内默认均匀；开场后也按任务组内规则选工作动作。`AnimationSelection` 区分普通、吸边、任务与其他随机场景。保留 Swift 的手动频率及偏爱，相对原默认频率按比例调整场景权重；若用户只启用当前这一段，继续默认待机。减少重复只作用于其他随机互动、额外动作与移动，不再改变普通待机或吸边比例。

TaskActivity.line 使用真实公开摘要、结构化操作或回复状态；displayTitle 单独保留个性台词。ToolOperation 集中分类图标，主气泡及概览复用，不解析原始脚本猜测操作。InlineStatusLayout 共用文字基线与盲文单元字形定位；ProgressMarqueeView 用 CoreText 显式基线绘制文字，固定图标按同一规则定位。

TranscriptActions 的末尾占位不含换行，避免 TextKit extraLineFragment 重复继承底栏整块高度；TranscriptRenderer 仅在轮次之间追加分隔。展开／收起仍由 MessageTextView 实测底栏并通知气泡重排，保留自定义宽高比与屏幕边界。

刘海设置没有按屏幕类型禁用控件：外接／无刘海屏允许保存开关，实际吸附仍由 NotchDockGeometry 检查当前屏幕。没有有效刘海时不触发顶部收纳，左右吸边正常。动作 renderScale 是素材本身的绘制倍率，独立于桌宠整体大小及收纳尺寸上限产生的额外缩放；左右吸边只旋转和侧移，刘海收纳还会倒挂与缩小，二者的视觉效果并不等同。


刘海收纳比例追加调整：尺寸上限由刘海宽度改为桌宠默认 100% 的 256pt 画布，窗口初始化、大小调整与收纳上限共用 PetController.defaultCanvasSize。几何倍率为 min(1,默认画布／当前画布)，不改动作 renderScale 或用户 petPercent。收纳后改变桌宠大小仍实时生效，召回恢复原大小。动作与活动／吸边新增 notchExposurePercent（默认 55%，40%～85%，滑块步长 5%），纳入搜索、恢复和偏好导入导出；开关及滑块不按屏幕类型置灰。露出高度由轮廓比例计算，调整只重绘及重排气泡，不重新加载素材。

吸边召回时记录当前窗口位置，与现有旋转／缩放使用同一 0.3 秒三次缓出进度，逐帧移向屏幕安全范围内的原位置；结束清理吸边状态时位置已到达目标，避免最后一帧单独 move 造成瞬移。左右与刘海吸边共用，保留原手势与 displayLink。


收进刘海默认开启，偏好读取沿用“已保存值优先，否则默认值”的既有规则；不迁移覆盖用户显式关闭的选择。只在拖到有效刘海位置并松开时触发，不在启动时自动收纳。

SDK 兼容性：内建屏幕查询 CGDisplayIsBuiltin 自 macOS 10.2 可用，safeAreaInsets 与辅助区域自 macOS 12 可用，均早于项目最低 macOS 14 SDK／部署目标。识别代码不依赖 full／glass 外观档位，也不以 Retina 倍率代替内建屏幕判断。该代码在 SDK 26.5、27.2、arm64／macOS 14 目标完成类型检查；SDK 14／15 全工程尚未实测。辅助区域为当前显示模式的可用区域，不是机型硬件清单。

进展思考图标使用系统 ellipsis.bubble，与原生回复气泡区分。主气泡及概览继续从 TaskActivity.symbolName 获取同一固定图标，图标不跟随文字滚动。
