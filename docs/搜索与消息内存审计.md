# 搜索、消息与运行内存审计

日期：2026-11-04。范围：joseph/dev，0.7.2-rc.4 源码，覆盖本机搜索、历史消息、临时卡片，以及长思考与连续工具调用。本文跟踪源码持有关系与已完成验证，原始采样和实施流水保留在本机。

## 本轮结论

2 MiB 只限制 HistoryDatabase 的正文读取缓存，不能概括整个消息系统。关闭记录历史只停止写入，运行会话仍追加 Turn，未保存正文继续驻留内存。20 张近期卡片与 20 轮历史页是数量边界，没有字节预算。当前没有证据可把实际进程每次增长全部归因于某一个路径。

已修复确定的多余持有；没有删除可读历史、丢弃草稿、截断助手消息，也没有改变记录开关的冻结／不补录语义。

## 搜索与查询清单

| 路径 | 保存内容与边界 | 生命周期结论 |
| --- | --- | --- |
| 历史全文筛选 HistorySearch / ChatUI | 当前查询签名、匹配会话与短摘要；数据库正文 LRU 最多 16 条／2 MiB | 隐藏／最小化不扫描；不是逐查询累加缓存。本轮关闭窗口同时清空侧栏结果与快照，保留查询词与草稿 |
| 当前正文查找、高亮、文件路径展开 | 当前页匹配范围与 FileEditPresentation 的原始富文本、展开 ID | 跟随当前页替换；关闭历史释放正文、布局及展开来源；本轮修正空会话仍保留上一页渲染缓存和会话删除使用错误缓存键 |
| 设置搜索 SettingsSearch | 懒加载固定元数据索引、当前结果 | 不加载历史正文，不按查询累计；切换页面清空锚点和动作回调，索引不会预建所有设置页。关闭设置仍保留当前页面及有限元数据 |
| 会话选择器 ConversationPicker | 打开时的完整会话数组与过滤结果 | 原来关闭仍保留 contentViewController；本轮通过 popoverDidClose 释放，包含点击外部关闭 |
| 模型列表与会话模型设置 | 每个输入入口保留当前模型列表与会话选择字符串 | 不是全文搜索；目录／请求身份控制异步回执，删除会话清理选择，无逐查询正文缓存 |
| 外部数据库观察 DesktopHistoryReader | 最近一天最多 40 个会话、每个最近 3 轮、每轮最多 200 items；另补仍在观察／待同步轮次 | 是扫描范围，补查使 40×3 不是绝对上限。连接与语句按读取生命周期释放；historyValues 每秒替换，tracked／fingerprints 离开扫描范围清理。指纹共享 Swift 字符串，不能按份数直接乘内存 |
| 外部实时观察 DesktopApprovalReader | 活跃目标轮次的公开进展和审批详情 | rc.3 已裁剪旧轮次 items；停止订阅、过期及关闭清理。完整 IPC 帧仍需先接收解析，目标轮次的审批差异不能随意丢弃 |
| 标题、发送前状态、问题身份与模型配置查询 | 查询所需元数据／问题 ID，回执后局部对象释放 | 不维护历史搜索结果全集；明确提交前仍读取当前状态 |
| 工具中的 webSearch / commandActions.search | 展示 Codex 提供的查询词、命令和操作摘要 | 桌宠不执行这些搜索，也不缓存网页结果；不要和历史／设置搜索混为一谈 |
| 更新检查、额度查询、磁盘缓存 | 更新 URLSession 忽略本地缓存；额度每次请求；磁盘清理另有 URLCache 清理 | 与正文 LRU 分离；没有用旧额度缓存代替新查询 |

## 消息与显示持有清单

| 持有者 | 当前边界／修正 | 尚存成本 |
| --- | --- | --- |
| HistoryStore / HistoryBodyReference | 开启记录时提交后卸载正文；不可变版本由运行对象和保存快照共享；写入队列只保留最新 pending 文档 | 关闭记录、只读或保存失败时未提交正文仍在 RAM；不能重新落盘关闭期间正文来降低 RAM |
| TranscriptRenderer / MessageTextView | 当前页最多 20 轮；关闭替换排版器，本轮补空页／删除失效 | 单条与单页字节没有上限；当前文本与缓存富文本有同时存在的成本 |
| BubbleCardStore | 默认 20 张，设置 5～100；同 ID 更新，新增时淘汰较老非保护卡片 | 当前阅读／新卡／待处理请求受保护，数量可超过设定；原文长度无预算；历史仍可另持有同内容 |
| Bubble 当前显示 | 本轮淡出结束释放正文、排版、滚动正文视图、临时刷新闭包和操作回调；重开取消旧清理；问卷保存在对应卡片 | 保留下来的卡片原文和问卷草稿继续占用，属于可再次阅读／操作的状态 |
| ChatReplyPreview | 本轮以 bodyReference.id 判断变化，只保存短摘要 | 版本变化时仍解析最新正文形成摘要；未进一步改写 Markdown 摘要算法 |
| TaskMessageAccumulator | 本轮最终消息输出后释放聚合器，进展投影只保留文件路径、不再重复持有 diff | 执行期间累计助手消息、公开思考摘要、命令步骤与 item 元数据；长思考／工具数量大仍会增长；不是原始隐藏思考 |
| CodexConnection 接收队列 | 本轮解析后在接收线程忽略未消费通知（包括工具输出增量）；item／turn 完成通知过滤原始思考、工具输出、图像数据；每条 JSON 解析使用 autoreleasepool | 仍需接收／解析完整单条数据；真实需要消费的增量仍逐条排主线程，未量化积压峰值。RPC 回执和审批请求保持原样 |
| 草稿 / 错误恢复 / 悬停提示 | 草稿按入口／会话保留、删除会话清理；本轮错误面板先断开按钮回调再移除控件，提示淡出清空文本 | 未提交草稿不按缓存淘汰；错误面板关闭窗口但尚未处理时保留恢复能力 |

## 定向证据与边界

- 隔离夹具使用临时目录，生成 24 轮各约 256 KiB 的不同正文。关闭记录：inline_bodies=24，body_payload_bytes=6,291,518，database_cache_bytes=0。开启记录并等待保存：inline_bodies=0，database_cache_bytes=0。这是对象正文载荷统计，不是完整 App footprint，也不是用户真实会话内容。
- 释放检查覆盖历史旧排版器 weak 引用、草稿／选择保留、搜索弹出控制器、错误恢复捕获对象、空页缓存、气泡排版器、问卷隐藏／重开／解决及淡出中重开。错误面板仅删除子视图时捕获对象仍被保留，显式清除回调后检查通过。
- 新增卡片淘汰、工具通知过滤、审批／RPC 保留及差异摘要检查全部通过；Apple Silicon 开发可执行文件 build-only 与 git diff --check 通过。未打包或替换用户正在运行的 App。
- 验证使用本地隔离夹具，未连接模型或使用真实对话；夹具按开发分支规则保留本地。最低目标机 M1 Air 与完整 App 的长期内存走势尚未验收。

## 下一步应解决的结构问题

1. 为历史富文本与近期卡片制定字节预算／惰性再渲染策略；“20 条”无法约束单条巨型消息，保护请求仍须保留完整操作详情。
2. 明确关闭记录时本次运行历史的保留范围：当前语义要求不落盘且保留阅读，持续新内容必然增加 RAM。变更应作为明确的产品行为决定，不能在释放修复中悄悄删掉内容。
3. 对真实长思考／工具刷屏量化接收队列峰值和本轮摘要／操作元数据，再决定合并显示更新或缩小进展状态；保留消息身份、完成事件、审批和回执顺序。
